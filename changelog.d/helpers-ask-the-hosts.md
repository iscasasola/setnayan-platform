## 2026-10-31 · feat(helpers): "Ask the hosts" — a helper asks for more on one part; every host is told in the app [migration]

Owner 2026-10-31: "yes" to building "Ask the hosts" (DECISION_LOG "A HELPER SEES THEIR OWN ACCESS AS THE FIRST ROW OF HOME ⚙ EVENT SETTINGS — read-only, with 'Ask the hosts'"). In-app only: no email, no push (standing rule "no new emails without his word").

- **Helper** (Home ⚙ › Your access): one button, **Ask the hosts**, under the parts. It is the only press there besides the ⓘ. It opens the house Sheet: **More on** (one PickMenu of the parts a host could raise for them, each showing its current level) · **What do you need?** (optional, 140 characters) · **Send**. After Send the sheet closes in place and the button reads **Asked · 3:04 PM**. A refusal is shown in the sheet, in words. The button is hidden when nothing could be raised.
- **Hosts**: every host (`event_members` couple) gets one notice: "Helper Tita Lorna asks for more access · Seat plan". It links to `?settings=1&row=access&person=<seat>&part=<area>`, which opens People with access **on that helper's row**. That row now says what they asked for: "Asked for more · Seat plan · 3:04 PM" (the viewer's own notices from the last 7 days).
- **Migrations** `20271299515167_access_more_asked_notification_type` (enum value only, in its own file) and `20271299854365_a_helper_asks_the_hosts_for_more`: one SECURITY DEFINER door, `ask_hosts_for_more_access(event, part, note)`, executable by `authenticated`. It checks the caller's own accepted, live seat, so a limited helper may ask too (asking is not editing). It refuses parts a host cannot set, and refuses a second ask for the same part within 24 hours. Concurrent presses are serialised by locking the seat row with FOR UPDATE. It writes notices straight into `notifications` and never calls `emitNotification`. It grants nothing. No new table: the notices are the record.
- **No new server action**: the action budget sits at its ceiling (1226/1226). The Send calls the door from the one browser client, the same way `mark-group-read.tsx` does. The database is the server-side check.
- Exposure baseline: +1 line (the door: `secdef=yes exec=authenticated search_path=public, pg_temp`). Port baseline: +5 additions.
- Guards: `tests/db/a-helper-asks-the-hosts.db.test.ts` checks that every host is notified, a second ask the same day is refused, and a non-member, guest, unaccepted, removed or signed-out caller cannot ask. It also checks that nothing reaches `email_deliveries`. It was sabotaged twice and went red both times. `app/dashboard/[eventId]/_components/a-helper-asks-the-hosts.test.ts` checks that the kind is on neither allowlist, the door's parts match `DELEGATE_AREA_LABEL`, the UI shows exactly two presses, the link lands on the helper, and the host row reads its own asks. It was sabotaged with an email-allowlist entry and went red. `a-helper-sees-their-own-access.test.ts` now allows the second press.
- Lab: `/dev/home-lab?as=helper&settings=1` (`&asked=1` shows the state after Send). `/dev/home-lab?settings=1&row=access&asked=1&person=00000000-0000-4000-8000-0000000b0002` shows the hosts' side.
