## 2026-09-11 · security(moodboard, site media): a row can no longer make the server sign or copy somebody else's private file

**The hole (measured on production 2026-09-10, not read from migrations).** `moodboard_finish_render` and `moodboard_attach_gallery_copy` are SECURITY DEFINER, executable by `authenticated`, and checked only that the caller "may act" on the render's event — a gate that admits ANY event member (couple, guest, vendor, coordinator), and `moodboard_begin_render(…, 0)` makes a render row for nothing. Neither checked the key. Every render key is then read back with the ADMIN R2 credentials from the PRIVATE `setnayan-thread-files` bucket — which also holds payment-proof screenshots and chat files: presigned in the couple's gallery and the admin all-creations page, presigned for OTHER couples by the inspiration pool, and COPIED into the public bucket when another couple picks it. So a guest could stamp `payment-proof/…` onto a render and be handed a signed link to a stranger's receipt. The same shape sat on the couple-writable website media on `events` (hero photo, hero film, site music, `our_photos`, the Save-the-Date upload background): `authenticated` holds column UPDATE, a direct PATCH bypasses every server action, and the PUBLIC wedding site / editorial / showcase / OG cards resolve them through `displayUrlForStoredAsset`, which presigns any bucket it is named.

**Write side (migration `20271220579615_a_render_key_is_its_own`).**
- Both render RPCs now return FALSE for any key but the render's own, compared byte-for-byte: `renders/<event_id>/<render_id>.(png|jpg|webp)` and `render-gallery/<event_id>/<render_id>.jpg`. Equality, not a prefix test — a leading space, `R2://`, a `..` segment or a lookalike is simply not equal.
- Named CHECKs `event_renders_image_key_is_its_own` / `event_renders_gallery_image_key_is_its_own` refuse every other writer, service role included (which also makes a forged render un-featurable).
- CHECK `events_site_media_names_only_the_public_bucket`: those five columns may only begin with `r2://setnayan-media/`, `http(s)://` or `/` (or be blank) — an allow-list anchored at the first character, so the resolver's `trim()` cannot turn an accepted value into a private ref. Pinned by bucket, not folder: the media bucket is public anyway, and the living hero files under `living-heroes/`.
- Measured before writing it: `event_renders` 0 rows; `events` holds one site-media value (site music, own folder) — both constraints validate with no backfill. Exposure baseline unchanged (6617 facts).

**Serve side (app).**
- `lib/moodboard-render-keys.ts` (pure) is the one derivation of a render's keys — the writer mints with it, every reader checks with it. `lib/moodboard-render-serve.ts` holds the only three doors from a render row to storage (`signOwnRenderImage`, `signPooledGalleryImage`, `readPooledGalleryBytes`), each asking "is this the row's own object?" before touching R2. The couple's gallery, the admin page, the post-render preview, the pool browse and the pick copy all go through them; `shapeRenderPoolPage` withholds a forged pooled key before its signer is ever called.
- `lib/site-media-ref.ts` (pure): `siteMediaServeRef` returns only a trim-stable public-bucket ref or a plain URL — wrapped around every read of those columns on the public site, the editorial, the showcase, both OG cards and the couple's own editors.

**Guards.** `tests/db/a-render-key-is-its-own.db.test.ts` (11, as a real non-superuser `authenticated` role, every refusal beside a positive control; the SERVE half plants a forged key around the constraint in a rolled-back transaction and proves the app gates refuse it). `lib/moodboard-render-keys.test.ts` (7, incl. the SQL equality lists = the writer's extensions), `lib/site-media-ref.test.ts` (5, incl. a whitespace/scheme/bucket property corpus and "everything the CHECK admits is safe to sign"), `lib/every-render-read-is-pinned.test.ts` (4, derived from the source tree). Three existing render db tests moved to real own keys (a made-up key would now prove nothing). 11 mutations, each red, restored.

**Kept, and named for the owner:** any event member — guests included — may still start a render (spending the couple's credits) and give share consent on the couple's behalf, because `moodboard_render_caller_may_act` has no member_type filter. That is a product decision; this change only pins the keys.
