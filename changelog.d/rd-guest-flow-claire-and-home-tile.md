## 2026-10-04 · fix(guest-flow): the personal link always lands on the invitation (cause + capture) · the iPhone home-screen tile keeps the guest in

**I4 — "the Claire bug" — cause found.** Measured on production (839e898, maria-and-jose test guest): a chat app's link-preview fetcher (`facebookexternalhit`, used by Messenger/Facebook/iMessage) followed the personal link's 307s and ended on the bare Event Hub `/{slug}` (no cookie jar: og:url `/{slug}`) or on the landing (with a jar: og:url the site root). The card drawn under the link opens that address — with no token — so tapping the CARD (not the blue text) met "Get inside", signed in or out, on one phone and not on another. The fetcher also redeemed the guest's link (a pass minted for a robot, a false "opened" scan). Second, smaller hole: a chat app's own "Open in Safari / external browser" opens the address bar, `/{slug}/invite/enter`, which never held the token — simulator: that address in a fresh Safari opens the Event Hub as a stranger.

- `app/[slug]/page.tsx`: a link-preview fetcher on `?invite=` now gets a 200 in place (no redirect, no redeem) whose og:url/canonical IS the personal link (noindex). People are never classed as fetchers — the table test holds Messenger/Facebook/Instagram/Line/Viber in-app UAs, Safari, Chrome, the home-screen tile and the Setnayan app to "take the hop".
- Re-entry code (`lib/guest-reentry.ts` + `.server.ts`, table `guest_reentry_codes`): server-issued 32 random bytes, stored only as sha256, spent ONCE by `/{slug}/redeem?k=` for the guest's normal pass (never the raw pass token, never an account session). Landing code (30 min) rides the landing address after the redeem and inside in-app browsers; tile code (24 h) rides the per-event manifest's `start_url` from the thank-you after a Yes (I9).
- Evidence: every personal-link visit that does not end on the landing writes ONE grouped Problems-log row (`recordFault` → `app_fault_issues`, kind DEAD_END, action `guest-pass-hop#<rule>`) with the rule, path template, hop steps, UA family, what the phone held (a kind) and the service-worker rule — never a token, code or name. Rules: `enter:no-key`, `enter:guest-gone`, `redeem:missing`, `redeem:unknown-token`, `reentry:refused`.

Guards: `lib/guest-pass-hop.test.ts` §§ 5–8, `lib/guest-reentry.test.ts`, `tests/db/a-guest-re-entry-code-is-single-use.db.test.ts`; three neighbouring guards follow the new shape (`the-last-door-hands-over-the-qr`, `the-personal-link-opens-the-landing`, `the-shortcut-line-is-on-the-thank-you-only`).

SPEC IMPACT: None to a locked decision. New table `guest_reentry_codes` (service-only, RLS at CREATE, no browser grant). The 30-minute / 24-hour code windows are engineering defaults (`REENTRY_TTL_SECONDS`), not money — flagged for the owner.
