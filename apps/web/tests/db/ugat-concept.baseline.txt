# Ugat concept-coverage baseline — things that look like a subsystem but are not
# (yet) on /admin/ugat/map.
#
# FORMAT   <table or prefix_*> | <reason>
# READ BY  tests/db/ugat-concept-coverage.db.test.ts  (inside a REQUIRED check)
#
# ── HOW TO USE THIS FILE ───────────────────────────────────────────────────
# The check fails when something subsystem-shaped has no home. There are two
# honest answers, and adding a line here is the SECOND one:
#
#   1. It IS a concept  → add a node to UGAT_TYPES in lib/ugat/graph.ts.
#                         The check greens itself; do NOT also add a line here.
#   2. It is NOT        → one line here, with a real reason.
#
# A key ending in `_*` covers a whole family, so declining a 13-table subsystem
# is one readable line rather than thirteen identical ones.
#
# ── THE TWO PREFIXES, AND WHY THEY DIFFER ──────────────────────────────────
# `declined`    — genuinely not a product entity. Ops, internal tooling,
#                 deferred verticals. These stay off the map permanently.
# `map-backlog` — a REAL product subsystem the map has never covered. This is an
#                 admission, not a decision. Each one is a candidate node.
#
# That distinction is the whole point of seeding this honestly. When the guard
# first ran (2026-07-30) it found 59 unaccounted things, and the great majority
# were real product — Papic (13 tables), the person spine, packages, seating, the
# song desk. The map shipped as "slice 1", platform-level only, and had never
# covered them. Writing `declined` against Papic would have been a lie that read
# as green, so the backlog is recorded instead of hidden.
#
# The count of `map-backlog` lines is a debt figure. It should shrink.
