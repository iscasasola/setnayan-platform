## 2026-09-11 · security(storage): the generic signer signs only the public bucket; every private read is scoped to its own folder (N4 part 3)

Found by N3 (#5415): `displayUrlForStoredAsset` presigned an `r2://` ref in ANY bucket, with the admin R2 credentials, for whoever's page asked — and browser-writable columns reach it (`event_editorial.draft_json`, `guests.photo_url`, `vendor_profiles.logo_url`: `authenticated` INSERT/UPDATE, production 2026-09-11). One value naming `setnayan-thread-files` (payment proofs, chat files) or `setnayan-vendor-verification` (government IDs) made the server hand the viewer a signed link to a stranger's private file.

- `displayUrlForStoredAsset` (and everything built on it: the list, logo and guest-photo helpers, 171 call sites) now applies `publicBucketServeRef` — the SAME allow-list as #5415's `siteMediaServeRef` / the website-media CHECK — before it can presign: a private, unknown or malformed ref returns `null` (every caller already has a placeholder). `displayUrlForStdBackground`, which presigned `ref.bucket` directly, got the same gate.
- NEW `displayUrlForPrivateStoredAsset(value, policy)` (+ list form, + `displayUrlForCatalogueArt`): signs only a ref in the policy's bucket under one of its tenant folders (`parseClientRef`). Every private reader was found by enumerating every private-bucket WRITER (12 `<FileUpload>` sites + the server writers) and following each column; each now names its folder: payment proofs on the admin queue, the couple's order page and the vendor's booking-fee page (`paymentProofPolicy` = the order's own `payments/<order>/` + the inline-checkout `<event|user>/` folders — composed from the two write policies); dispute evidence (couple page and — newly readable — the admin flag page) → `disputeEvidencePolicy`; paperwork scans → `paperworkScanPolicy`; host payment receipts on the vendor thread → `budgetPaymentProofPolicy`; a shop's verification papers → `vendorVerificationDocPolicy`; catalogue sample art on Explore, onboarding and the taxonomy studio → `catalogueArtPolicy`.
- The dispute action kept ANY `r2://` ref as "evidence" (a fourth browser-reachable door): it now keeps only the uploader's own `events/<id>/disputes/` folder.
- Production (read-only): the only private refs stored anywhere are 4 payment screenshots, all inside the new policy; no private column holds a legacy URL.
- Guard `lib/the-generic-signer-is-public-only.test.ts` (9): the rule by behaviour (20 private/malformed spellings refused), the signer's gate order, the scoped signer, 11 private readers pinned to their policy, the dispute write half, the exact private-uploader inventory (a new one fails until its reader is named), and a pinned list of the only files allowed to call a raw signer.
