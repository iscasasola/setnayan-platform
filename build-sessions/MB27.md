# MB27 — one mark everywhere

**Model · effort: Opus · high.** Pixel work on the client-side stamp, and a double-marking check
across two paths. Same weight as MB20, which this completes.

**Owner rulings (2026-09-05, "follow your recommendations"):**

- **One mark everywhere: the web address.** Every photograph Setnayan marks carries
  `WWW.SETNAYAN.COM` (plus the seal for event-linked photos, as MB20 built). The bare word
  `SETNAYAN` on the marketplace pool goes away. The point of the mark is that someone who sees
  the photo outside the app knows where to go.
- **Videos are deferred to Phase 2.** No video watermarking in V1. Record it; do not build it.
- **Paid Make-it-real renders keep the stamp they already have** — see below; no build.

## What oversight measured (2026-09-05, `origin/main`)

Two watermark paths exist, and they disagree on the text:

| path | module | text today | non-test callers |
|---|---|---|---|
| server, `sharp` | `lib/watermark-server.ts` | `WATERMARK_TEXT = 'WWW.SETNAYAN.COM'` (stamp) · `SETNAYAN / CELEBRATION` (seal) | `vendor-dashboard/moodboard-library/actions.ts` (gallery uploads, variant by `markVariantForSource`) · `lib/moodboard-gallery-copy.ts` (render pool copy) |
| client, Canvas | `lib/watermark.ts` | default `text: 'SETNAYAN'` | `app/_components/file-upload.tsx` (**the marketplace pool** — vendor showcase / service photos, `position: 'bottom-right', opacity: 0.55`) · `app/admin/moodboard-library/_components/library-editor.tsx` (admin library uploads) |

- **Renders are already right.** `moodboard-gallery-copy.ts` calls `watermarkImageBytes(bytes)`
  with no variant, and the default is `'stamp'` = `WWW.SETNAYAN.COM`. Owner question 4 is closed
  by the code as it stands. Your only job there is a guard: assert the gallery copy is produced
  with the stamp variant, so a later refactor cannot drift it to the seal or to nothing.
- **The client stamp sizes by real ink.** `lib/watermark.ts` uses `ctx.measureText(text)` with
  `fontSize = max(18, 4% of the short edge)`. That is the honest measurement MB20 had to add to
  the sharp path — so the longer text will not shear the way the server plate did. It may still
  be **illegible**: at the 18 px floor, `WWW.SETNAYAN.COM` in a 600-weight monospace is ~190 px
  of ink on an image that may be 400 px wide. Measure legibility, not just fit.

## The build

### Part 1 · The client stamp says the web address

- `lib/watermark.ts`: default `text` becomes `'WWW.SETNAYAN.COM'`. Import the string from
  `watermark-server.ts`'s `WATERMARK_TEXT`? **No** — that module pulls `sharp`, which cannot ship
  to the browser. Define one shared constant in a dependency-free module
  (`lib/watermark-text.ts`) and have BOTH modules import it, so the two paths cannot disagree
  again. A guard asserts both modules import it and neither carries its own literal.
- Both callers keep their options; only the text changes. Pixel-verify at the sizes the
  marketplace actually uploads (read `file-upload.tsx`'s resize cap): ink inside the plate with
  the padding MB20 specified, and the plate inside the image at every corner position the
  component allows. Assert **bounds and padding**, not presence
  ([[presence-of-ink-is-not-fit-of-ink]]).

### Part 2 · Nothing is marked twice

The admin library editor marks on the client (`watermarkFile`) and then submits to
`admin/moodboard-library/actions.ts`. Read that action: if it marks again on the server, one of
the two goes. The server mark is the one that survives (it is the one MB20 measured and the one
the vendor path uses); the client call in `library-editor.tsx` is removed. If it does NOT mark
again, leave the client mark and say so in the report with the line you read. Either way, a guard:
a fixture pushed through the full admin path carries exactly one mark region.

### Part 3 · Renders (guard only)

`lib/moodboard-gallery-copy.ts` — a test that the copy is produced with variant `'stamp'`. Sabotage
by passing `'seal'` → red; by dropping the `watermarkImageBytes` call → red (MB20's presence
guards may already cover the second; if so, cite them, do not duplicate).

### Part 4 · Videos (record only)

Add the ruling to the `lib/watermark.ts` docblock and the `watermark-server.ts` header: *video
marking is Phase 2 by owner ruling 2026-09-05; `watermarkFile`/`watermarkImageBytes` are images
only and refuse video MIME types loudly rather than passing them through unmarked.* If they do not
refuse today, make them — an unmarked video that "succeeds" is the failure-looks-like-success
disease.

## Out of lane

in the `watermark.ts` docblock. MB26's files.
