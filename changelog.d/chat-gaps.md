## 2026-11-10 · fix(chat): the six chat gaps — live read + Seen, co-host names, team notices, team senders, payments at once, Ask for access in the (+)

Owner, 8 Nov 2026: *"yes build them"* (the chat gaps) and *"suppliers also get ask for access"*. In-app notices only, no new email.

1. **Unread / Seen.** A message that arrives while the chat is open marks the thread read: ONE debounced `markThreadRead` per burst, only while the tab is in view (`lib/chat-read-live.ts`, run by the stream, which is mounted only where the Chat view is on screen, so the picked client's Details and Quotation still mark nothing). "Seen" is now live state, moved by a `read` broadcast on the stream's existing `chat-presence-${threadId}` channel (no new socket). Messages with a NULL sender (Setnayan lines, the auto-reply) never count as unread for anyone: migration `20271336137492_a_line_nobody_wrote_is_never_unread` changes one predicate in `count_unread_message_threads`, `unread_message_threads_by_event` and `unread_message_threads_by_vendor`, and `lib/couple-inbox.ts` mirrors it.
2. **Co-host names.** On the hosts' side "mine" is the signed-in person (`lib/chat-bubble-owner.ts`). Another co-host's run is drawn on the left with their first name (`readThreadReceipts` names co-hosts in the same `users` read). Runs split per person (`lib/chat-bubble-runs.ts`), and "Delivered/Seen" never sits under a co-host's message.
3. **Notices.** `notifyOtherParty`: when a host writes, the shop owner keeps the notice as it shipped. The shop's team members who may chat get it in the app, and so do the OTHER hosts in the thread and the event's coordinators. When the shop writes, the hosts IN the thread are told (no longer every event host: since `20271330575424` a host who left, or was never added, cannot open the thread), and the coordinators are told in the app. Every added recipient gets the new in-app-only type `chat_message_in_app` (enum `20271337067968`, push level normal, declared `app_only`), so nobody new is emailed.
4. **Team members send.** `chat-send.ts` admits the shop's team members that `chat_messages_member_insert` admits (owner/admin; below admin on an event their assigned service serves), via `lib/chat-shop-people.server.ts`. RLS is unchanged. The app-layer block check (`resolveCounterpartyUserIds`) now counts the whole team, the same set as `chat_pair_is_blocked`. Team members can block and report, and a host can reply privately to a team member.
5. **Payments at once.** A Setnayan line arriving live in the open chat triggers ONE debounced `router.refresh()` of the money around it (`lib/chat-live-refresh.ts`). A payment ask now posts its own line ("Payment asked · ₱X · due …").
6. **Ask for access in the supplier (+).** A new row on every supplier's and the coordinator's Tools sheet, held shut until they are booked, like Payment and Form. Its card (`cards/access-step-card.tsx`) is one `PickMenu` and calls the SHIPPED `askHostForAccess`, so who may ask and who answers are unchanged. That ask now posts a plain line into the thread ("… asked to open: Seat plan, Guest list — the hosts answer in Access requests."). No new server action.
