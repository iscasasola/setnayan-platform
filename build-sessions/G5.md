## The delta

1. **An event-dated couple audience.** Add the ability for a window to qualify on the EVENT's
   date rather than only on wall-clock — the owner's *"for an event for a specific date"* and
   *"a specific date/range"*. Decide and justify ONE of:
   - a new `audience_type` (e.g. `events_dated_in_window`), or
   - nullable `event_date_from` / `event_date_to` columns that any couple audience may carry.
   Prefer the columns if `all_couples` should be able to carry a date filter without a new
   audience value; prefer a new audience if the two must never mix. Say which and why in the PR.
   ⚠ The `audience_type` CHECK **re-lists its whole vocabulary** and G4 rewrote it — read
   G4's migration (`promo_free_windows_cohort_deals`) and extend it the same careful way,
   including its `DO $$` block that drops the older differently-named constraint. A re-listed
   CHECK that forgets a value fails only at ALTER-validation against real rows; the PGlite
   replay is what catches it (memory: `a-re-listed-check-vocabulary-drops-a-later-value`).
2. **Thread the event through the gate.** `isSkuFreeForCouplesNow(serviceKey)` must become
   event-aware (extra optional arg, or a sibling function) and the call sites in
   `apps/web/lib/entitlements.ts` must pass the event id they already hold. Keep the
   no-event behaviour byte-identical to today so nothing that cannot supply an event changes.
   A pure, unit-tested predicate — `coupleWindowCoversEvent(window, eventDate)` — is the piece
   worth testing hardest; mirror `vendorQualifiedAt`'s shape.
3. **Services covered.** Confirm `covered_service_keys` reaches Papic, Live Stream and Event
   Hub Pro. **Do not guess the service codes** — resolve them:
   `git grep -n "LIVE_STUDIO" origin/main -- apps/web/lib | head` and search the live catalogue
   (`platform_retail_catalog_v2`) for the Event Hub Pro row. If a service's gate does not funnel
   through `eventSkuActive`/`eventOwnsSku`/`isSkuFreeForCouplesNow`, a promo cannot free it —
   say so explicitly in the PR rather than implying coverage you did not verify. ⚠ **Never derive
   a price or a SKU from a code comment or a doc — read the catalogue table.**
4. **Admin surface.** `/admin/gifts` gains the couple-side deal creator (audience · window ·
   event-date range · covered services multi-select · required reason), reusing the existing
   free-windows action rather than forking it, with the rows appearing in the same unified list
   G4 extended. One page — that was the owner's whole ask.
5. **Provably inert while dark:** a test that with `PROMO_FREE_WINDOWS_ENABLED` unset, a live
   event-dated window frees nothing for a matching event.
