## 2026-08-15 · fix(year): the empty tile stops claiming things it has not established, and five of my own defects from #4452

An adversarial pass over **my own** merged PR ([#4452](https://github.com/iscasasola/setnayan-platform/pull/4452)) — five lenses, two skeptics per candidate — found six real defects. Five are mine, introduced yesterday. Every one below was **re-verified by hand against the branch before acting**, not taken from the agent's report.

**1 · 🚨 THE TILE ASSERTED SOMETHING FALSE, TWO WAYS.** It said *"Nothing comes back around yet."* — a claim about a person's whole life, made from a list filtered to **366 days**.

- A couple whose wedding is more than a year out reaches it. **Measured: a 2028-02-14 wedding yields ZERO moments today.** The events board directly above the tile renders that wedding as a card with its date; the tile underneath told them nothing comes back around. **Same screen, two contradictory statements**, and the sentence is the one a person believes.
- A refused read reaches it identically. `return null` used to make that invisible — a silent absence, but never a false claim. **Turning it into a tile turned it into a lie**, and the comment at the read site had already named that exact risk while fixing only the logging half.

🔑 **A COMPONENT THAT REPLACES `null` INHERITS THE OBLIGATION TO BE TRUE.** Hiding says nothing; speaking is a claim, and every state that reaches it has to make the claim correct. Copy is now scoped to the window the derivation actually used (*"Nothing in the year ahead yet"*), and `unsure` swaps the claim out entirely for a read that failed. **The two doors stay in both branches** — holding the door open is what that branch is for.

**2 · 🚨 "YOUR 1ST BIRTHDAY · A MILESTONE YEAR", SHOWN TO AN ADULT.** The guard tested `next.age < 1` and its comment claimed that covered *"today's year or in the future (a typo, or a date picker's default)"*. **It covered half.** `age` comes off the NEXT occurrence, so once a mistyped current-year month/day had passed, the occurrence rolled into next year and `age` came back **1** — the first rung of the PH ladder. **Measured over every in-year date on 2026-08-15: 210 of 336 rendered a gold, highlighted "Worth planning for" card reading "Your 1st birthday"; the other 126 were silently dropped.** Same slip, confident falsehood or nothing, depending only on the month. The profile field is a bare `<input type="date">` with no `max`, the save action checks only the *shape*, and no CHECK constraint exists — so this is the ordinary way in, not an edge case. Now rejected on the **birth year**, which is the rule the original comment described. A genuine 1st birthday from a prior birth year still counts — pinned by its own test so the fix cannot become "reject age 1".

**3 · 🚨 ONE CALENDAR DAY PRINTED TWICE.** `/onboarding/[type]` hardcodes `recurs: true` for `event_type = 'birthday'`, so anyone who created their own birthday there **and** has the date on their profile got two rows on one date — *"My 30th Birthday"* and *"Your birthday — turning 30"*. Measured. On the home strip only three rows are visible, so the duplicate ate two and pushed a real moment behind *"Show 1 more"*. `mergeSelfMoments` now drops the profile line when an event holds that day — **the event wins**: it is tappable and carries the name the person chose. Shared by both surfaces, because two callers merging by hand is two chances to merge differently.

**4 · 🛡 MY OWN GUARD WAS DECORATION, AND ITS DOCBLOCK SAID OTHERWISE.** It claimed *"each one was mutation-checked by deleting the line it guards"*. Only one spelling had been. Re-measured with `<EmptyYear` counts printed before → after, **three other spellings of the identical regression kept it 6/6 GREEN**: `if (!moments.length) return null;` · `if (moments.length === 0) { return null; }` · `if (moments.length < 1) return null;`. The orphaned `EmptyYear` kept holding both `<Link>`s so the href count never moved, and nothing removes an unreferenced local component (no `noUnusedLocals`, eslint is `next/core-web-vitals` only).

🔑 **MATCH THE ACT, NOT ONE SPELLING OF IT** — the strip is now asserted to render `<EmptyYear>` and to contain **no `return null` at all**, a rule with no variants to enumerate. Every read goes through the shared `stripComments` lexer, because these files describe the very hrefs they are counted for: replacing the real `<Link>` with a JSX comment naming the href left the unstripped version fully green. **Fourth time a text-searching guard in this repo has matched its own explanation.**

🪤 **AND THE REPLACEMENT HAD THE PREFIX TRAP.** `/unsure/` still matches `unsureX` — the same shape as `f.event_dateX` — so renaming the prop kept the new guard green (7 → 7, red=false). Anchored with `\b` and counted. **Caught by the mutation run, not by reading it.**

🪤 **AND MY MUTATION HARNESS MEASURED THE WRONG TEXT**, reporting a *correct* guard as "sabotage did not land" because it counted raw source where the guard counts stripped source. **An unverified "decorative" verdict is as wrong as an unverified pass.**

**5 · The Year page's birthday read dropped its `error`** while its twin in the same diff checked it. A rejection would print *"Add your birthday"* to somebody who typed theirs months ago — forever, with nothing in the logs.

**6 · Two docblocks stated the opposite of the code.** The Year page still claimed *"zero PII in this first cut (no birthdate path)"* twelve lines above the read that broke it — **a privacy claim, and the DPO is the owner** — and the launcher call site still promised the strip *"renders nothing when there are no anchors"*, the exact behaviour #4452 removed. Also corrected: a test comment pointing at `year-door.test.ts`, **a file that does not exist**, which would have told the next reader coverage existed under a name they could not find.

🛡 **15 mutations, every one landed (counts printed before → after) and every one caught; baseline green after restore.** New tests pin the wiring (`buildSelfMoments` reaching both surfaces — the whole feature could previously be deleted with the suite green), the dedup, the current-year rejection in **both** directions, and the no-double-emit promise the docblock already made.
