## 2026-09-11 · fix(vendors): a shop with 0 reviews shows "New to Setnayan", never "☆ 0.0 · 0" — and the letter monogram stops taking a stray "(" or "&" as a character

Owner ruling 2026-09-11 (DECISION_LOG.md, seen on the couple's bench "more" row, Saysay card): a shop with no reviews must show "New", never "☆ 0.0 · 0". Found in the same pass, fixed as a defect (no ruling needed): the shop/vendor letter monogram took the literal first CHARACTER of a name's first and last whitespace-separated word, so "Saysay Live Band & Hosting (FIXTURE)" rendered "S(".

**A · rating display.** Root cause: `vendor_market_stats.avg_rating_overall` is `COALESCE(..., 0)` at the database layer — never NULL — so a bare `rating ?? null` / `rating != null` check let a brand-new shop's 0 straight through as if it were a real average. The one shared source both the category-search overlay and the bench "more" row read from — `searchCategoryVendors` in `app/dashboard/[eventId]/vendors/_actions/category-search.ts` — now nulls the rating unless it's a real positive number, matching the guard every other rating-consuming surface in this codebase already used. Two new exports in `lib/reviews.ts` — `isNewToSetnayan(rating, reviewCount)` and `NEW_TO_SETNAYAN_LABEL` (the shop page's own copy, reused verbatim) — are the one place the "does this shop have anything to average yet" decision is made; every fixed surface renders the label instead of hiding or (the old bug) printing a fake average, but only when `reviewCount` is a known number for a real marketplace-linked vendor — an off-platform/manual pick with no enrichment data stays silent rather than being falsely called "New".

Surfaces fixed: `app/dashboard/[eventId]/vendors/_components/shortlist-categories.tsx` (the bench "more" row — the exact reported bug; the bench inline marketplace-search results; the main shortlisted-vendor bench card), `.../category-search-overlay.tsx` (Find overlay), `.../plan-budget-accordion.tsx` (Plan & Budget's vendor cards + its compare sheet), `.../vendor-quickview-inspector.tsx` (desktop quick-view), `app/(shell)/explore/_components/vendor-card.tsx` (the marketplace/explore grid + search, was already guarded against "0.0" but showed a lowercase "new" instead of the owner's exact copy), `.../compare/page.tsx` (the comparison table, same "new"→copy fix, plus suppressing the now-misleading "(0 reviews)"), `.../folder-vendors-section.tsx` (explore folder previews, previously hid the row entirely), `app/tour/vendors/_components/tour-shortlist.tsx` (the pre-signup guided tour, real `vendor_market_stats` data).

**Checked and left alone:** the shop page's own header (`app/v/[slug]/page.tsx`) already hides its rating chip entirely when there are no reviews ("an honest empty state, never a fake 0.0" — pre-existing comment) — nothing to fix there, and its separate empty-reviews BLOCK further down is F2's to own, per the brief. Out of scope by file ownership: `lib/vendors.ts`, service-card files, `app/api/og/v/**` (HONEST SHOP, open PR #5423 — checked its file list, no overlap).

**B · letter monogram.** New shared helper `lib/shop-initials.ts` (`shopInitials(name, maxChars = 2, fallback = '·')`) tokenizes on Unicode letters/digits only (`\p{L}\p{N}+`) instead of splitting on whitespace and taking a raw first character — punctuation, symbols, "&" and brackets can never be candidates. Takes the first character of the first two real tokens ("Saysay Live Band & Hosting (FIXTURE)" → "SL", the business's own first two words, not the trailing "(FIXTURE)" artifact). Every duplicate `initials`/`initialsOf` implementation that shared the exact bug now delegates to it: `shortlist-categories.tsx`, `plan-budget-accordion.tsx`, `vendor-quickview-inspector.tsx`, `app/tour/vendors/_components/tour-shortlist.tsx`, `app/_components/plan3d/booth-vendor-card.tsx` (all vendor monograms), and `app/_components/frontdoor/front-door-feed.tsx` / `front-door-results.tsx` (shop monograms — fixing the shared `initialsOf` there also fixed its co-located story-owner / own-event-space call sites, which carried the identical bug).

**Left alone (people/guest initials, not shop/vendor):** `app/_components/plan3d/guest-avatar.tsx` (`initialsFromName`, 3D guest avatars) shares the identical bug shape but is out of this brief's scope; `lib/guests.ts` (`guestInitials`) operates on structured `first_name`/`last_name` fields, not a free-text split, so the bracket/ampersand class of bug doesn't apply the same way; `app/admin/users/[userId]/page.tsx`, `app/vendor-dashboard/clients/[eventId]/page.tsx`, `app/vendor-dashboard/customers/_components/customers-roster.tsx`, `app/dashboard/[eventId]/details/_components/governed-fields.tsx`, `app/_components/frontdoor/rail-data.ts` (the signed-in account's own avatar) are all people, not shops. `lib/event-initials.ts` is a different concept (an event/couple monogram that deliberately keeps "&", e.g. "C&I") — untouched.
