## 2026-08-27 · fix(admin): the learned-phrases screen is in the menu, and its one unsavable option saves

Two dangling ends from the admin-search stream.

### A fix nobody can reach is no fix

`/admin/search-memory` ships, is served, both its buttons work, and production
already holds a real row on it. It was in **no menu** — and therefore absent
from *"All surfaces"* too, which derives from the same source — so the only way
to reach it was to type into the search box. Which is where you already are
when the box has answered you wrong. This feature has hit that shape once
before. It now sits beside *Entity map* in **Set up**.

⚠ **The recorded trap was honoured and measured.** A menu item's searchable
words are label + group label + description + alias — **the route is not among
them** — so moving this page from map-sourced to menu-sourced deletes the
route string it used to match on. The four phrasings that reach it were run
before and after the change:

| query | before | after |
|---|---|---|
| "teach the search box" | 1st | 1st |
| "delete search phrase" | 1st | 1st |
| "search phrases" | 1st | 1st |
| "what has the search box learned" | 1st | 1st |

Top-5 orderings byte-identical in all four; total destination count unchanged
at 86 (it changed band, it did not duplicate). An alias line carries the words
the route string used to supply. Both generated files were **regenerated by
their own scripts, never hand-edited**.

### One option in "teach it this instead" could never be saved

Of the 86 destinations offered, exactly one — **My account** — was refused by
the database the instant you pressed Save, showing a raw error with no way to
know that option never could have worked.

**The app-side rule is made authoritative and the database now agrees with it.**
The validator deliberately accepts that address, because *My account* is a
curated destination outside the console — the admin doorway has no other path
to changing a password or signing out other devices. The database said the
opposite. Measured reasons the app rule wins:

1. **It was never a security boundary.** Read out of production: the table has
   row security on with **zero policies and zero browser grants**, table- or
   column-level. No browser can reach it. Both writers are service-role admin
   actions that already run the app check.
2. **It was both too loose and too tight** — it admitted a made-up console
   address (a dead link) while refusing a real reachable page.
3. **It was live on both writers and one failed silently:** the assistant's
   learner only *logs* a failed write, so a correct answer of *My account* was
   never remembered and every repeat paid for another model call, forever.

The constraint now states the floor it was actually reaching for — a learned
phrase must never navigate an admin **off Setnayan** — as a site-relative,
non-protocol-relative path. Verified read-only against production: the real
page is now allowed, while protocol-relative, backslash-smuggled, absolute and
bare-root addresses stay refused. Deliberately **not** an allow-list of
non-console destinations: a list would be a bill to keep paying.
