## 2026-10-04 · feat(motion): Fade · Move (arrow grid, 8 directions) · Size · Blur combine; Speed; details under each effect

An element's In and Out — and a scene's — are now FOUR independent effects that combine: **Fade** (Fade · None) · **Move** (8 directions — 4 edges + 4 corners — · None) · **Size** (Grow · Shrink · None) · **Blur** (Blur · None), plus **Speed ▾** Fast · Regular · Gentle (the shipped quick · normal · slow). One vocabulary for both layers: `lib/motion-effects.ts`.

- **Data** (`HubElementMotion`, `lib/element-style.ts`): `{ in?: MotionFx, out?: MotionFx, speed?, outSpeed?, delay?, during?, timeline? }`, `MotionFx = { fade?: true, move?: one of 8, size?: grow|shrink (|settle on an Out), blur?: true }` — all closed sets, absent = None/Regular. Scenes (`HubSectionCanvas`) gain `inFx` / `outFx`, stored ONLY for a combination the shipped `in`+`inFrom` / `out`+`outTo` cannot say (`hubSceneFxFields`); anything they can say is written as them.
- **Old values map on read, no data migration:** `rise` → Fade + Move from below · `fade` → Fade · `lift` → Fade + Move to the top · `settle` → Fade + "Settle back" (carried as its own Size value on an Out — the four cannot say 96.5%) · `stay` → no Out · Duration quick/slow → Speed Fast/Gentle · #6019's Still/Calm/Editorial/Cinematic as before. A shipped combination keeps its shipped `@keyframes` (`el-in-rise`, `el-out-lift`, `hub-in-movefade-left` …), so every stored value renders byte-for-byte as before — held by a table test against renders frozen from `origin/main` (`lib/motion-shipped-renders.fixture.json`).
- **CSS:** any other combination is ONE composed keyframe per end — `el-in-mix` / `el-out-mix` (+ `-p` Play twin), `hub-in-mix` / `hub-out-mix` — whose far end is three custom properties built from closed-set keys only (opacity 0|1 · `translate3d(±d, ±d, 0) scale(0.85|1.15|0.965|1)` · `blur(8px)|none`). Written only inside the shipped `prefers-reduced-motion: no-preference` gate → reduced motion stays still. Keyframes live in `globals.css` (CSS, ~1 KB) — nothing added to the shared JS chunk. A part moving sideways clips its scene on x, as scenes already did.
- **Speed following the scroll** = how far the thumb travels (Fast `entry 0% entry 100%` / Gentle `entry 0% cover 50%`; Out Fast `exit 0% exit 50%` / Gentle `cover 50% exit 100%`); Regular is exactly the shipped range; a pinned Scrub scene keeps its shipped ranges.
- **Maker:** the part sheet's Motion section runs in the order a guest sees it — 1 Comes in (Fade ▾ · Move ▾ · Size ▾ · Blur ▾, then Speed ▾ + Delay ▾ only once an In effect is on; no Delay when it follows the scroll) → 2 While on screen (During ▾) → 3 Goes out (same four + its own Speed; hidden when it plays once) → 4 When it plays ▾. A fresh part opens short. **Move ▾** is the shared `PickMenu` with a new `grid` mode: closed it reads "↗ From lower-left"; open it is a 3×3 grid of ARROWS OF TRAVEL (centre ● None), each named "Comes in from lower-left". The scene inspector's Comes in / Goes out use the same rows (+ "Back to Auto").
- **Part sheet sections** are one segmented control — Text · Motion · Arrange — the chosen one in the wine token (`bg-mulberry`, `ISeg tone="wine"`).
- **Part sheet on a phone** (`lib/element-sheet-state.ts`, a pure reducer): a tap on the canvas outside the part folds the sheet to a slim bar ("Names · Motion ▴"); tap the bar to restore; another part switches the sheet, same section; the same part changes nothing; the handle folds; × closes. The scrim over the canvas is gone from the part sheet so those taps reach it; the canvas reports a tap on no section (`tapOutside`).
- Pro-at-Apply unchanged: a part's `motion` and a scene's `inFx`/`outFx` are look keys (`HUB_CANVAS_LOOK_KEYS` / `HUB_CANVAS_MOTION_KEYS`).
