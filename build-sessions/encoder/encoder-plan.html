Setnayan's own encoder

Nine sessions to replace OBS with your own desktop app — so a couple opens Setnayan instead of configuring streaming software the week of their wedding.

The decision is already made. Path A — the desktop app encodes — owner-ruled 3 Sept. ₱0 per wedding against the relay's ₱500–1,000 every wedding. This is the how, not the whether.

The architecture, and the one thing not to build

The obvious build is "the app screen-captures the program window." Don't. The web app already runs inside the Tauri webview, so frames can be produced in-process.

The nine sessions

E0

The spike — does any of this work here?

Opus 5 · high · 1–2 d

Two questions that can reshape everything. Does the Tauri webview expose VideoEncoder and AudioEncoder on macOS and Windows? And does the desktop build still compile — it has not run since 25 June.

Blocking. WebCodecs is confirmed in Safari 26; whether WKWebView exposes it is undocumented either way. If it doesn't, the whole shape changes and you want to know on day one, not day fourteen.

E1

Program surface → canvas

Sonnet 5 · high · 2–3 d

Composite the program frame in-process. The pattern exists in reel-render.ts, and the WebRTC streams do not taint the canvas — unlike that file's cross-origin R2 clips, which is its main hazard.

E2

Overlays on canvas + the drift guard

Sonnet 5 · high · 3–4 d

Monogram, lower third, event QR, POWERED BY SETNAYAN. These are React DOM and must be re-drawn — a second renderer for the same fact.

🚩 The revenue-protecting session, and the one most likely to be left uncovered. The decision stays server-side (decideWatermark, the air decision); only the drawing is duplicated. The encoder consumes ProgramFrame.overlay and never re-derives it. Guard must assert every WatermarkReason variant is handled, so a new variant fails the build rather than silently airing unbranded.

E3

WebCodecs encode — H.264 + AAC

Sonnet 5 · high · 2–3 d

Video is proven in-repo. AAC audio is new — and audio arrives as a track off the MediaStream, which is precisely how this design stops the vows being lost to an OS routing setting.

E4

IPC transport + backpressure

Sonnet 5 · high · 2 d

Frames from webview to Rust. Dropping frames must degrade, never stall — a stalled pipeline mid-ceremony is the failure this whole project exists to remove.

E5

RTMP client + FLV mux in Rust

Opus 5 · high · 4–6 d

A build-or-buy decision as much as systems code: native Rust, or an ffmpeg sidecar at ~2–3 days but +80 MB and an LGPL/GPL call you would be making for the whole product.

E6

The stream key never reaches the renderer

Sonnet 5 · high · 1–2 d

A bearer credential for a channel other couples' weddings stream on. Fetched server-side, handed to Rust, never to the webview. Never logged, never in an error string, never in Sentry, redacted in diagnostics.

Precedent to follow, not shortcut: live_studio_channel_grants is RLS-enabled with no policy — service-role only — exactly so a platform credential is not exposed row-wise to event members.

E7

Cross-platform build, signing, notarization

Sonnet 5 · high · 3–5 d

Routinely underestimated. macOS Developer ID + notarization already has a fallback path; Windows is still unsigned, which means a SmartScreen warning — the same category of friction as Google's unverified-app screen, on a wedding week.

E8

Auto-updater

Sonnet 5 · high · 2–3 d

Not in the original 19–28 day estimate, and not optional. The Tauri shell meta-refreshes to setnayan.com, so web changes reach users instantly — but the native half is version-locked. Without this, an encoder bug means asking couples to reinstall the week of their wedding.

E9

Acceptance run

Sonnet 5 · medium · 1–2 d

A real end-to-end rehearsal on both operating systems: phones join, cut between them, overlays correct, stream reaches YouTube, health strip honest, kill the network and confirm it degrades rather than lies.

✓ LS4

Failure reaches the controller — already shipped

merged 2 Sept

The scope budgeted 2–3 days for "encoder death is visible." getYoutubeStreamStatus is already wired, quota-costed and mutation-tested. That work is done and carries over unchanged.

Wall-clock is shorter than the sum: E5 and E6 depend only on the IPC contract, so they can run alongside E1–E4. E7 and E8 need a working binary. E9 is last.

Do not start E1 before E0 comes back. Every session after it assumes WebCodecs works inside the Tauri webview. That is confirmed for Safari 26 and undocumented for WKWebView — one day of spike against three weeks of rework.

What this does not buy you

It does not remove the laptop. Nothing can — a browser cannot open an RTMP socket, on any device. It replaces "bring a laptop, install OBS, configure a custom RTMP server, paste a stream key, set up window capture" with "bring a laptop, open Setnayan."

And it is not B4. B4 is a phone app pushing one stream per kit camera, for Roam. Different input, different topology. Building this leaves Roam with no capture path, and any plan treating them as one item under-scopes Roam.
