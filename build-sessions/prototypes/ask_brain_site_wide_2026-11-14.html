One storage decision this needs (why the ruling's "widen the table" cannot be add-only)

The existing memory table refuses any address that is not an admin page (a check on the address), and keeps exactly one row per phrase (a uniqueness rule). Couple and supplier pages, and "yours first", both need those two rules relaxed — which is not an add-only change. The add-only way is a new, separate table for the site-wide picks (phrase, page, person, role, count, last used), readable only by its owner and by staff, with the admin table left exactly as it is.

Recommendation: the new table. It keeps every rule on the admin memory, needs no change to existing rows, and lets couples, suppliers and staff learn separately by design.
