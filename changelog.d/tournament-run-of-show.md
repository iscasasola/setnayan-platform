## 2026-08-01 · fix(schedule): a tournament's run-of-show is a competition day, not a dinner party

A `tournament` event opened its day-of schedule to **"Guest arrival · Opening & program · Meal · Main highlights · Socials"** — the generic party spine. It had no authored program in `lib/schedule-run-of-show.ts`, so it fell through to `GENERIC`. Meanwhile the SAME event type's checklist (`lib/checklist-event-type-defs.ts` → `TOURNAMENT_TEMPLATE`, `tier2Core: ['officials','awards','catering','medic']`) already knew the day is brackets, officials, medics and medals. The two surfaces disagreed about what the event IS, and the schedule was the one telling the host to plan cocktails.

- **New `TOURNAMENT` program** in `lib/schedule-run-of-show.ts`, registered in the existing `PROGRAMS` registry alongside the other eight authored types. The spine is the real shape of a Filipino barangay/school meet: call time & venue setup (private crew beat) → team check-in & registration → opening ceremony → *parade of teams & muses* → rules briefing & bracket draw → elimination round → lunch → quarterfinals & semifinals → championship match → awarding ceremony → closing remarks & send-off. Times are contiguous and non-overlapping, 06:30–18:15.
- **Enriched only from signals the host actually captured.** The notes read the REAL `signature_details` keys authored in `lib/onboarding/specialty-catalog.ts` under `"tournament"` — `sport_discipline` · `tournament_format` · `divisions[].division` · `teams[].team_name` / `teams[].team_muse` · `organizer_sponsor` · `opening_parade` · `awards[]`. Enum tokens are humanized through explicit label maps; an unrecognized token degrades to an unenriched note rather than leaking `double_elimination` into host-facing copy.
- **One gated beat, so we never promise a beat nobody planned.** "Parade of teams & muses" shows only when `opening_parade` was captured or a team named a muse — the liga community layer the specialty catalog calls out ("Team muses + Muse of the League + the opening parade"). Every other beat is core to any bracket event and always shows, so a host who skipped the specialty form still gets a usable competition day.
- A `liga_season` format is told, in the elimination-round note, that a season spans several game days and this is one game-day template — the schedule surface is single-day anchored.

**No other event type changes.** This is a pure addition to the `PROGRAMS` map; `GENERIC` and every existing authored program are untouched, and weddings never reach this module at all (`buildRunOfShowSeed` returns `[]` for them — they own `buildScheduleSeed` in `lib/schedule.ts`). Verified by the full unit suite: 5906 tests, 0 failures.

The one existing test that asserted `tournament` falls back to the generic spine was retargeted to `celebration` — a real, enabled type with no authored program for which that spine is genuinely correct.

### Two things found while doing this, deliberately NOT fixed here

1. **`anchorIso` puts the seed on the wrong DAY west of UTC.** It UTC-parses the date (`new Date('2026-11-14')` → midnight UTC) and then sets **local** hours on it, so in any timezone behind UTC the entire seed lands on the day BEFORE the event. This is pre-existing and shared by every authored program (and mirrored by `schedule.ts`'s wedding seed): the sibling test `blocks are anchored to the event date and time-ordered` already fails under `TZ=America/New_York` on unmodified `origin/main`. It is latent in prod only because Vercel runs UTC — but that has its own half: on a UTC runtime the authored *clock* times are stored as UTC, so a 17:00 debut beat renders to a PH host at 01:00 the next day. Fixing it moves every event type's seeded times, so it needs its own PR and its own sign-off. The new tournament tests are written to be timezone-independent and do not encode the bug.
2. **`date` and `hangout` are also inheriting the party spine.** Of the enabled types, `celebration` / `gala_night` / `simple_event` / `date` / `hangout` / `tournament` had no authored program. `celebration`, `gala_night` and `simple_event` are a fair fit for `GENERIC`; a two-person dinner `date` and a barkada `hangout` being seeded "Guest arrival · Socials" is the same class of mismatch as tournament, just quieter. Left alone — one type per PR.

No migration. `event_type_profiles.schedule_seed_key` was NOT used as the dispatch key: it is `NULL` for every non-wedding type in prod (verified by SELECT) and nothing consumes it — `event-type-profile.ts` still carries its "PHASE 0 CONTRACT: nothing consumes this yet" note. Routing through it would have required a migration to populate the column plus plumbing the profile into the seed action, for no behavioural gain over the `event_type` dispatch the other eight programs already use.
