# MB24 — the modern-minimalist bride gets her gown back

**Model · effort: Opus · high.** Small in lines, but it extends MB23's pixel guard, and a pixel
guard extended carelessly stays green through its own sabotage (MB20, MB23 both proved it).

**Prerequisite: MB23 (PR #5190) MERGED.** Branch from `origin/main` after it lands. MB23 deleted
this asset's colour range by migration `20271205919528` because it could never work; MB24 gives
the asset a range that can.

## What oversight measured (2026-09-05)

- Live asset: `moodboard_library_assets` row with `storage_path LIKE '%figure_attire/modern-minimalist/bride.svg'`,
  276 `<path>`s, no `<rect>`, no raster. **Path 0** is `M 0 0 L 2048 0 L 2048 2048 L 0 2048 z`
  filled `rgb(236,235,231)` = `#ECEBE7` — a full-canvas backdrop. **Path 2** is the gown, same
  fill. ΔE between them is 0.0 by construction. 23 further small paths (veil, bouquet highlights)
  share the fill.
- **The re-cut is done and is in this folder:** `build-sessions/assets/mb24/modern-minimalist-bride.svg`
  (path 0 removed, an XML comment left in its place saying why; the original is beside it as
  `modern-minimalist-bride.ORIGINAL.svg`). Rendered through `sharp` at 512 px and measured:
  corners `rgba(0,0,0,0)`, gown centre `rgb(236,235,231)`, opaque coverage 32.8 %. That is the
  shape the other 30 backdrop-free figures already have.

## The build

1. **Host it app-served, like the florals** — `apps/web/public/moodboard-seed/figure_attire/modern-minimalist/bride.svg`.
   The florals precedent (`/moodboard-seed/florals/*.webp`) is live, same-origin, and
   canvas-recolourable without CORS. Do NOT ask the owner to upload to R2: that is exactly the
   debt MB14 still carries, and a same-key overwrite on `r2.dev` would also be served stale from
   browser caches. Copy the file byte-for-byte from `build-sessions/assets/mb24/`; record its
   sha256 in the migration header.
2. **Migration** (allocate with `pnpm migration:new`, above `20271205919528`):
   - `UPDATE` that row's `storage_path` to `/moodboard-seed/figure_attire/modern-minimalist/bride.svg`.
     Match on the `%figure_attire/modern-minimalist/bride.svg` suffix, `asset_type = 'figure_attire'`;
     assert exactly one row with a `DO $$ … RAISE` block — a 0- or 2-row update must fail loudly.
   - `INSERT` the range: `slot_id 1`, `sampled_hex '#ECEBE7'`, `region_label 'attire'`, and a
     tolerance you MEASURE, not inherit — start from MB23's retuned values (10–12) and confirm by
     pixel that the gown AND its shading recolour while the (now transparent) surround stays at
     alpha 0. The veil shares the fill; recolouring it with the gown is correct, it is attire.
3. **Extend MB23's guards, do not add a parallel one:**
   - `the-background-never-wears-the-palette.test.ts` parses tolerances out of the migration and
     rasterises the figures. Add this asset to its set; it must load the app-served path from
     `public/`, not from a URL. Sabotage: reinstate path 0 in the SVG → red; set the tolerance to
     40 → red; point the migration at a different suffix → red.
   - `attire-recolours-because-the-query-asks.test.ts` — the figure pick prefers a variant WITH
     a range. After MB24 the modern-minimalist bride HAS one again; assert she is pickable, so
     a future range deletion cannot silently drop her from the section.
4. **MB23's placeholder predicate** (`lib/moodboard-library-placeholder.ts`) must accept an
   app-relative `/moodboard-seed/…` path exactly as it accepts the florals. If it does not,
   that is a bug in the predicate, not a reason to host on R2.
