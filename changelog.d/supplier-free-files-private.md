## 2026-11-22 · fix(suppliers): a Free shop's files stay inside the app (subscriptions item J)

Owner-locked 22 Nov (DECISION_LOG "SUPPLIER PLAN ANTI-ABUSE RULES LOCKED" (8); build spec § ★ J): an unverified (Free) shop's files are viewable only inside the app, never as public or shareable links, so Free can't be used as free public file hosting. A verified shop's public surfaces work exactly as before.

- **The rule, one place:** `lib/free-shop-files.ts` (pure). Verified shop → today's resolver, unchanged. Not verified + signed-in viewer → a signed link that lives 15 minutes (`FREE_SHOP_FILE_TTL_SECONDS`). Not verified + stranger (signed out, the cached stranger copy, a link preview, a crawler) → no URL at all. An unread verification state is never public. The shop is read off the key every supplier upload is filed under (`vendors/<shop>/…`, `vendor-originals/<shop>`, `vendor-payment-qr/<shop>/…`, `supplier-files/<shop>/…`).
- **The signer, extended (not a second one):** `lib/supplier-file-sign.server.ts` gains `shopFileUrl` / `ownShopFileUrl` / `shopFileUrls` / `readShopFileServes` (one batched `vendor_profiles` read for pages that show other shops' files; a failed read withholds, never publishes). A Free file goes only through `displayUrlForStoredAsset` at the short TTL (media bucket) or the policy-checked private signer inside its own shop's folder, never the public host and never the 24 h signer. A legacy absolute URL is never passed through.
- **Wired:** the public shop page `/{shop}` and `/v/{shop}` (logo, portfolio, hero, service photos, showcase video, covers, work albums incl. Papic portfolio photos, partner logos), its link-preview card `/api/og/v/{shop}` (wordmark only for a Free shop), and the couple's signed-in screens that used the permanent public address: Suppliers tab covers, bench/Find service cards, the supplier sheet's photos.
- **Guards:** new `lib/free-shop-files.test.ts` (rule by behaviour; key shapes; the short TTL through the stable-address signer; the signer never reaches the public host; every surface routed) — sabotage-checked twice. Pins in `bench-service-card`, `the-service-cover-plays`, `booking-fee-top-up` and `public-url-takes-a-key-not-a-ref` moved to the new call shape, same intent.

Not covered (listed in the PR): the bytes still sit in the public `setnayan-media` bucket, so a key seen in a signed URL can be turned into a permanent public address by someone who knows the bucket's host — closing that needs Free uploads to land in a private bucket (the upload side, not this PR). The supplier's own dashboard pages and chat logos still use 24 h signed links.

SPEC IMPACT: None — implements spec § ★ J as written; no new ruling.
