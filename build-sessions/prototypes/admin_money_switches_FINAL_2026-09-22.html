In plain words

What changes 3 things

The existing fee form gains a promotion and a lock switch. The switch shows who it would affect before you press it. Every save writes an audit row, as the fee schedule already does.

What is NOT changing 3 things

No new page, no menu row, no route — four files in the pricing page that already exists. I first said this needed a new admin page joining four registries; I was wrong. The fee schedule itself is untouched. No migration — all three columns already exist.

What this cannot prove 3 limits

The count is baked in here; the real page reads it live, which is exactly why the “couldn’t check” state exists. Production has never been in the dangerous state — 2 charges, 0 unsettled — so that state is a scenario on the 2 real shops. Nothing has been built.

What I measured, and what it changed the re-order

The shipped section says its title twice — an h2 and the form’s own h4 — and carries two paragraphs saying the same thing before you reach a field, about 75 words. It also leads with the fee schedule, which is set once a year, above the switches you’d come here to change. So the words cut are the ones already there, and the order is inverted. The 4 shipped controls all survive.

Why this file has no scripts and what it cost

Your viewer does not run scripts, so the earlier version’s state buttons were dead for you — it looked like it worked. Every state here is a radio button and CSS. Lost: the figures no longer recompute as you type. Kept: every figure is still true — each was computed with the real fee maths and written in. The fee boxes and the lock switch are still real controls.
