## 2026-08-27 · fix(vendor-inquiries): the anonymised inquiry placeholder stops calling every organiser "a couple"

`inquiryPlaceholderLabel` — the identity-free line a supplier reads BEFORE accepting an inquiry, the one that decides whether they answer at all — opened with the hardcoded literal **"A couple"** for all seventeen event types. A funeral home read *"A couple planning a funeral in Manila"*. Sixth instance of "this product assumes every event is a wedding".

**The noun is now threaded in, not read.** `lib/inquiry-mask.ts` is deliberately dependency-free (safe to import anywhere + unit-testable) and resolving the noun needs a database read, so `inquiryPlaceholderLabel` gains a **REQUIRED `hostNoun` parameter with NO default** — the `PabuyaTrustNote` / `organizerPossessive` pattern from #4891. A seventh call site added later is a typecheck failure, never a silent drift back to "couple". Same required-prop treatment for the pure `buildInquiryCard`. `lib/inquiry-mask.server.ts` gains `inquiryHostNoun()` / `inquiryHostNounsByType()` — the ONE place that decides what "we do not know the type" means — and `fetchInquiryMaskMeta` now returns the noun beside the type and city. The two surfaces that did `?? {}` (a map lookup that can MISS, silently satisfying an optional shape) now pass an explicit exported `INQUIRY_MASK_UNKNOWN`.

**⚠ THE HOST NOUN, NOT THE ORGANISER NOUN — measured against prod, and it is wider than it looks.** FOUR of the seventeen seeded types carry an `organizer_noun` naming the person the event is ABOUT rather than the one planning it: `anniversary` · `birthday` · `debut` → `celebrant`, `graduation` → `graduate`. "A celebrant planning a debut" tells a supplier the debutante booked her own 18th; her parents did. `host_noun` is the axis that already answers *who does the admin work*, and `defaultHostNoun()` maps exactly these honoree nouns to `host`. **For a wedding both nouns are `couple`** — which is what makes this byte-identical on the only type anyone has booked.

**⚠ THE ARTICLE HAD TO VARY TOO.** The opener was a hardcoded `"A "` because "A couple" never changed. Four types carry `organizer`, which renders **"A organizer planning a corporate event"** — the same defect as the `a event`/`a anniversary` one fixed one layer up in `articleFor` the same week, and found the same way: by RENDERING all 17 types × 4 branches, never by reading the diff. The full before/after table is in the PR body.

**The read is public, and no session read of `events` is involved.** `event_type_profiles` carries a `USING (true)` SELECT policy for PUBLIC and grants SELECT on all 17 columns to `anon`/`authenticated` (measured in prod 2026-08-27), so the profile resolves from any session. Every call site already holds the event TYPE from an existing admin-scoped read — a vendor holds no `events` RLS — so nothing new touches `public.events` and the #4897 signed-out trap does not apply here. All six call sites are authenticated (vendor dashboard ×3, admin demo-vendors ×2, vendor overview) but the noun is derived from the admin-read type either way, so the path is correct rather than merely lucky.

**⚠ ONE DELIBERATE, VISIBLE CHANGE beyond the noun:** the fully-unknown branch (batched fact read returned no row) read *"A couple planning an event"* — the wedding assumption at exactly the moment we know nothing — and now reads **"A host planning an event"**, this repo's established neutral (`GENERIC_PROFILE`; `_lib/event-words.ts` states the rule).

**Identity is untouched.** The placeholder still takes only event type + city + the type's noun; nothing identifying is a parameter, so nothing identifying can reach it. A new test feeds ten identity-shaped values (names, initials, email, mobile, venue, street address, public URL, entity id) across five nouns × four branches and asserts none appears.

Tests — `lib/inquiry-mask.test.ts` extended (wedding literal pinned; article-follows-noun; lower-casing; the widened identity-leak guard) and new `lib/inquiry-mask-every-host.test.ts`: the seventeen types **derived** from `ANCHOR_BY_TYPE` with a floor, every type × every branch parsed and its two articles checked for agreement, only a wedding may open with "A couple", the `host_noun`-wins mechanism through `toProfile`, a derived source scan (comments stripped, floored) that every call site passes the noun, and a check that the parameter cannot quietly acquire a default. Imports are relative and asserted resolved, because an `@/…` alias under `tsx --test` can return empty named exports and run zero checks.

SPEC IMPACT: None — no priced SKU, schema, or owner-locked decision moves. The organiser vocabulary already existed in `event_type_profiles`; this consumes it on one more surface.
