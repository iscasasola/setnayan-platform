## 🚦 THE GATE — owner-set 2026-09-23

> **Owner, verbatim:** *"arrange all the builds and make sure no other session tries to build
> anything without going to you"* · *"you will analyze and check when they will be built"*

**No session starts a build without the Redesign Controller's authorisation. No exceptions,
including a one-line fix, including something the owner mentioned to you directly.**

If the owner tells a session to build something, that is **his** instruction and it stands — but
the session **tells the controller first** so the sequence and the queue are accounted for. The
controller does not overrule him; it schedules him.

**What a session does instead of building:**

1. **Measure it** — files, symbols, the trap, the open question. Reading and measuring are always open.
2. **Write it as a plan**, not code.
3. **Send it to the controller** with its size and what it blocks.
4. **Wait.** The controller decides *when*, against the sequence and the CI queue.

**Why the gate exists, measured today:** CI runs that normally take 5 minutes took **over an
hour** with ten jobs queued; three production builds died on a stale cache; and two sessions
independently rebuilt the same fix. **Throughput was never the constraint — the queue was.**

**Still open to every session without asking:** measuring, reading, writing plans, finishing a
build already authorised, and reporting a finding. **Closed:** starting a new branch, opening a
PR, arming auto-merge, touching production.

## What actually happened, 2026-09-23 → 24 — read this before the ranking

**11:25Z** — a merged icon fix reached production and every page inside an event began returning
an error page for signed-in users. The owner hit it on his own wedding, `cale-ice`.
**12:04Z** — the fix existed. **It could not deploy for seven hours.**

`main` was five routes over Vercel's hard 2048 ceiling, so **a fix was stuck behind a platform
limit**, not behind a bug.

**The cause, measured from `.vercel/output/config.json`: 1,248 of 2,050 routes are server
actions** — one per `"use server"` export, 1,247 of them across 336 files. Every save button
ever added. See `CONTROLLER.md` § 9 for the full anatomy and the three wrong theories that
preceded it.

**Fixed by removing 12 exported actions referenced nowhere in the tree** — 2050 → 2038,
measured locally before shipping.

### What this changes about the sequence

1. 🔴 **A server-action counter guard is now the highest-value unbuilt item.** 1,247 grew
   invisibly and the first warning was an outage. It is not on any rank below; it should be.
2. 🔴 **Sentry has been capturing production errors for months and nobody read it** — 137
   failures on `/api/website/qr/[slug]`, a guest-detail query broken for a month, five users
   hitting an unread-messages error since May. **That list should set the build order ahead of
   anything guessed from code.** `SENTRY_AUTH_TOKEN` is unset, so every stack is minified; the
   config self-enables the moment the owner provisions one.
3. ⚠ **Every rank below was measured before the outage.** Re-measure before acting.
