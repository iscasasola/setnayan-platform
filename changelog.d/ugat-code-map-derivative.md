## 2026-07-30 · feat(ugat): a committable code map — 33 MB of graph reduced to 16 kB of answer

The code-dependency view needs data on Vercel. The source knowledge graph is ~33 MB and git-excluded, so it cannot exist at build or run time. This is the derivative that can.

**17 areas, 53 bonds, 16.2 kB** — summarised from 31,200 nodes and 67,637 edges. You approved committing a file of roughly 0.5 MB; the useful artifact turned out **~30× smaller** than that budget.

### Three axes were tried before one worked

**Detected communities — rejected, and this is the important one.** The obvious move is to reuse the graph's own Louvain clusters. They are **not stable across rebuilds**: refreshing over 83 commits moved the count from 1,753 to 3,690 and auto-renamed 36. An admin view keyed on community ids would reshuffle its own groupings every regeneration, for reasons a reader cannot see. That is worse than no map.

**Directory bucketing — rejected.** Stable, but 1,644 buckets and 5,015 bonds. Barely more readable than the communities it replaced.

**Hand-declared path-prefix areas — chosen.** Stable by construction: the same file always lands in the same area, and the set changes only when a human edits the list. 17 areas is comparable to the entity map's 11 — an altitude a person can hold in their head.

### What it says

Everything points at **`lib`**. It absorbs 4,527 references from the couple dashboard, 2,162 from vendor, 1,851 from the public site, 1,690 from admin. The single heaviest file in the repo is `lib/supabase/admin.ts` at **589 dependents** — the RLS-bypassing client, which is also the biggest blast radius on the platform and worth knowing precisely rather than roughly.

### The `other` bucket earned its keep twice

`areaForPath` sends anything unmatched to `other` rather than dropping it, and `other` renders as a real node with a real count.

First generation: **20.8% unclassified** — because `apps/web/components/` exists alongside `apps/web/app/_components/` and I had only declared the second. Second: **16.5%** — because `graphify update` does **not** preserve the code-only filter used at first build, so the refreshed graph had absorbed changelog markdown. A *code* map silently summarising changelog prose is measuring the wrong thing.

Both were invisible defects that a catch-all rule would have hidden inside a plausible-looking bucket. Now **0.08%** (21 nodes of 25,162), and a test pins it under 2%.

Deliberately **not** a `prefix: ''` catch-all, and a test asserts an unknown top-level directory still lands in `other`. A rule matching everything makes the one mechanism that reveals your blind spots unreachable.

### What it deliberately does not keep

No per-file edge list, no symbol names, no call graph. Those are what make the source 33 MB, and none survive at area altitude. A future feature needing file-level blast radius should query the live graph via the graphify CLI rather than bloating a committed artifact back toward the size that made the original unusable.

Generated by `pnpm --filter @setnayan/web ugat:code-map`, developer-run rather than part of any build, since it needs the local graph. The output records its source commit and node/edge counts — a derivative without provenance is one you cannot trust, which is the same lesson the health registry taught this morning.

This is the artifact step. The console genericisation and the UI that reads this are separate, and land after.
