## 2026-07-27 · chore(ci): two CI guards for "one rule, written down twice" — the class that cost a full day

**The class.** Not a typo, and not a style complaint: a rule recorded in two places, which then drifts. Three confirmed instances landed on 2026-07-27 alone, in three unrelated features. A fee rate hand-typed into ~11 files — one of them a vendor's **BILL** — that kept saying "flat 5%" for three days after the maths became a taper. A page declaring `const keptItems` that **shadowed** the exported `keptItems` from `@/lib/vendor-packages`, so the receipt and the lock path disagreed about what a couple had bought (the exported one drops add-ons because there is no purchase path for them; the local one did not). Two pages **hand-typing a Supabase column list**, one of them missing `item_id` — making a removal filter compare against `undefined`, so it could never match — and `is_required`, where an absent boolean reads as FALSE and a line the vendor marked mandatory could silently vanish. Nothing catches any of these: shadowing is legal TypeScript, and every column name in a stale list is real, so PostgREST returns rows and the page is quietly wrong.

**GUARD 1 · shadowed exported helper** — `apps/web/lib/security/shadowed-export-scan.ts` + `.test.ts` (9 tests). Flags a local `const`/`let`/`var`/`function`/`class` in `apps/web` whose name is exported by a module **the same file already imports from**. That qualifier is the entire design, and it is measured rather than asserted: **21 qualified hits vs 8,677 without it — a 413× reduction.** T4 fails if those two numbers ever converge, because that is the moment the guard starts crying wolf, and a lint that cries wolf gets switched off. The trade is stated out loud in the test: 45 files declare their own `requireAdmin` and not one imports `lib/admin/require-admin.ts`, so all 45 are out of scope by design — nobody had the real one in reach. Two shapes are admitted: the file imports the NAME and re-declares it in an inner scope (legal TS, the local one wins), or it imports OTHER names from the owning module — the exact `keptItems` shape, reproduced verbatim from `39ac3c456^` as T3's positive control. Excluded: type-only imports/exports on both sides, a file that itself exports the name (that is a re-export, not a shadow), `*.test.ts(x)`/`*.spec.ts(x)`, and anything under `__tests__/`, `__mocks__/` or `tests/` — a local stub named after the helper it replaces is how you write a test double, and it fails loudly when wrong, which is the opposite of the production failure this exists for.

**GUARD 2 · omitted canonical column** — an **extension of `apps/web/lib/security/select-column-scan.ts`** (new PART 2), not a rival script; 6 new tests (T13–T18) alongside the existing 12, all still green. The existing scanner answers "does every column in this list exist?"; this answers the question underneath it — "is this list the same list the rest of the app uses?". It reuses the same `.from()`→`.select()` attribution, the same `parseSelectList`, and inherits the same documented limits; a second scanner would have drifted from the first exactly the way the two column lists drifted from each other. Canonical constants (`*_SELECT` / `*_COLUMNS`) learn their table **empirically**, from a real `.from('t').select(CONST)` somewhere in the repo — 35 constants are bound today. Binding is top-level-only: `` `${ITEM_SELECT}, parent_option_id` `` binds, `` `id, items:t(${ITEM_SELECT})` `` does not, because there the constant describes the embedded table. It also strips comments before matching, since `.select(` followed by an explanatory comment and *then* the constant is a real shape here (`vendors/packages/actions.ts`) — the original phantom-column path deliberately keeps reading raw source, and the asymmetry is written down in `lib/security/source-text.ts` rather than left to be discovered.

*The near-copy rule is two-sided, because one-sided fails the real bug.* The vendor workspace's stale list reproduced only 3 of `VENDOR_PACKAGE_ITEM_SELECT`'s 9 columns — 33%, which any "reproduces ≥N% of the constant" rule calls a legitimate narrow select. It was not: 3 of its own 4 columns came from the canonical list, so it was that list **trimmed**, and the trim took `item_id` and `is_required`. So the question is asked from both ends — the literal reproduces most of the constant (a stale paste), **or** the constant accounts for most of the literal (the constant, trimmed) — with a floor under the second, without which any 3-column select whose columns all appear in a 90-column export list scores 100% and gets accused of omitting 87. That was the first version's measured output. Tuned against the real tree: **104 facts across 24 sites**, and the historical workspace bug IS flagged (T13). A one-sided 0.3 threshold instead yields 123 facts including plainly-legitimate reads — a page wanting `venue_name` accused of omitting `love_story`. The grey zone that remains (a short literal fully covered by a short canonical list) is admitted in the docblock rather than hidden: it is the same shape as the bug and costs one reviewed baseline line, not a red build.

**The baseline is what makes both shippable** — `apps/web/scripts/dup-rule.baseline.txt`, **124 facts (21 shadow · 103 omit)**, mirroring the proven `supabase/security/exposure-surface.baseline.txt` pattern: **adding a line is a WIDENING and fails CI; removing a line is a NARROWING and passes silently.** The debt can only shrink and no NEW instance can land. That asymmetry is the design — a guard that goes red when you FIX something teaches people to stop fixing things. Regeneration is one command (`pnpm --filter @setnayan/web dup-rule:baseline`) and the header says, in plain words, what a new line means. **Keys are facts, not line numbers**: `shadow` is file⇥name⇥owning-module and `omit` is file⇥table⇥constant⇥column, so moving code within a file changes nothing and every line that does change in a diff is a real change in what the repo does. A `file:line` key re-shuffles on any unrelated import, arrives as 40 unreadable baseline edits, and the file stops being a review surface.

**Wiring.** `pnpm --filter @setnayan/web lint:dup-rule` runs as a step in the existing **typecheck + lint** job — it needs the TS scanners and that job has already installed, so a dedicated job would buy nothing but a second `pnpm install` per PR. The structural half is pure node and does get its own install-free job (`scripts/lint-dup-rule-baseline.mjs`, modelled on `lint-exposure-baseline.mjs`): header fact-counts match the body, per-kind floors, canonical ordering, unique and correctly-shaped keys, the mirrored `DUP_RULE_KINDS` constant has not drifted, the "adding a line is a widening" sentence is still in the header, and — the part that matters most — the guard is still wired into `package.json` and into `ci.yml` as a real `run:` step. A guard that does not run is worse than no guard, because it manufactures confidence.

**Anti-vacuity is enforced, not assumed.** The runner refuses to write a baseline from a broken scan and fails the check if fewer than 2,000 files are walked, fewer than 2,000 literal selects are found, or fewer than 10 canonical constants resolve to a table. T18 additionally pins `VENDOR_PACKAGE_ITEM_SELECT` as still bound to its table — if the guard ever stops watching the exact query that caused this, that is a failure, not a pass. Measured on the tree as it stands: **2,849 files · 3,078 literal selects · 35 bound canonical lists.**

**Deliberately NOT built: a generic "copy asserting a computed fact" guard.** The fee-rate instance is the third of the three, and it is the one that cannot be mechanised — there is no way to separate "flat 5%" in a doc comment from "flat 5%" in customer-facing copy from "5%" in an unrelated sentence without a false-positive rate that gets the whole thing switched off. Said here so the gap is a decision on the record rather than an oversight.

**No violations were fixed in this change.** The 124 baselined facts are debt captured for a separate pass — including `lib/budget.ts` reading `vendor_package_items` without `is_default_included` or `is_required` (67% of the canonical list reproduced), and `lib/vendor-autoreply/inbox-hook.ts` at 92% of `VENDOR_PACKAGE_SELECT`, missing only `unspent_credit_policy`.
