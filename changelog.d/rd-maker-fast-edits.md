## 2026-10-15 · perf(maker): style picks change the page at the tap, their Undo is instant, Apply and Mood Board picks no longer reload the Maker

The owner said: *"i still feel doing/editing using maker still takes so long before i see changes"*. These edits were measured on a production build of the Maker lab, with Chromium at 4× CPU and Fast 4G, using the lab's production-latency stand-ins. Each one waited on the server (`controller-2026-10-12/maker-speed/MEASURE.md`):

- **Undo after a style pick.** It took 8.7 s. A redraw save (`makerRedrawSave`) left an undo *barrier*, so Undo reloaded the whole Maker and a new canvas page. `makerRedrawSave` now carries its inverse (`{ undo }`). The inverse is the canvas's own section, copied at the tap (`lib/maker-scene-look.ts` `scenePictureUndo`). Undo lays that copy back at once, and the page then redraws in place.
- **Scene ◆ tile and part ◆ style card.** These took 4.1–4.3 s, with nothing changing until the save and a guest-page render had both finished. The tapped card is already the guest page drawn in that style, so its section is now laid over the canvas at the tap (`styleTap` → the bridge's `sceneLook` → `scene-look-lay.ts` `layScenePicture`). The page's own section is hidden, not removed, and comes back in the commit that brings the server's render. The part card's second whole-Maker render is gone (`makerNeedsRender`). Its count comes back with the save, and its pick lives in the row's own copy.
- **Mood Board attire and palette picks.** These saves were unheld: a whole-Maker render plus a reload of the hidden canvas, with the Maker busy for 7.1 s. They are now held, carry an inverse, and redraw in place. A copy kept per event preserves the pick if the board reopens before a render.
- **Apply.** It took ~9.8 s before the Maker settled. Apply now answers at its own write, with the count and "N changes are now live". The canvas keeps its page (`keepCanvasForRender`), and the Maker's render runs behind, outside the transition.
- **Next-stage warm.** It is no longer cancelled for the rest of the visit by the first save. A save on its way delays it. Once every save has landed (`MAKER_SAVES_QUIET_EVENT`), the next stage is warmed again, and only if it is not already kept. It is still one stage (owner ruling 2026-10-12).

Guards:
- New: `lib/a-style-pick-is-on-the-page-before-it-saves.test.ts`. It drives the real `styleTap`, `makerRedrawSave`, Undo journal, Undo runner and bridge on a stand-in page with a save that has not answered.
- Re-aimed to the new shapes, with each property kept: `the-other-stages-are-warmed-once`, `every-held-save-can-be-undone`, `every-maker-edit-shows-before-it-saves`, `a-style-pick-redraws-the-canvas-in-place`, `a-maker-pick-never-reloads-what-it-drew`, `a-draft-save-does-not-rerender-the-maker`, `the-bar-answers-an-action-that-never-came-back`, `the-picker-sets-one-colour-and-drafts-it`.
