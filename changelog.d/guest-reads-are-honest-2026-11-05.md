## 2026-11-05 · fix(guest): six refused reads no longer tell a guest — or their door crew — something false

A read that fails no longer renders the same as "not invited", "dead link", "used up" or "empty". Pattern: `lib/guests.ts` + `lib/guests-read-is-honest.test.ts`. Held by `lib/guest-pages-reads-are-honest.test.ts`. Every assertion there was checked by reverting the fix, which turns the test red.

- **Event Hub, a listed guest who is signed in.** `findGuestSeatForUser` turned a refused read into `null`, so the page said "You're not on the guest list for this event yet" with "Ask to join" or "Join as a guest". The reads now live in `lib/guest-seat-read.ts` (`readGuestSeatForUser`, which returns `{ seat, measured }`), and `findGuestSeatForUserMeasured` wraps them. On a public event a refused read shows "We couldn't check your invitation just now" + **Try again** (`GetInside` `seatUnread`). It never shows the not-listed words or a join button. On a private event it goes to the guest error page instead of the lock screen, whose words "ask your hosts to add you to the guest list" were the same false claim. The gate still never lets anyone in on a refused read.
- **Login ✕.** On a guest's card (`forGuest`, where `next` opens a real event) the ✕ now returns to that event instead of `/`.
- **Papic camera with a ceiling of 0.** This shows "The host hasn't opened your camera yet" from the first frame. It used to say "That's all 0 photos!" plus a thank-you. `capReason` starts as `'guest_spend_ceiling'` when `capApplies && total <= 0`. Only the couple can set a 0 ceiling, because the platform's ceiling is a flat 150. The caption under the shutter no longer adds "Your camera is all used up" either. To see this state, open `/dev/papic-camera-lab?ceiling=0` (dev only).
- **MY camera (`/papic/me/[token]`).** The guest and event reads now keep their errors and throw. The route has its own `error.tsx`, which re-uses the invitation boundary ("Your link is fine… Try again"). It no longer says "This link isn't active… replaced".
- **Check-in desk.** If `checkInGuest`'s guest read is refused, staff now see "Couldn't check that guest just now — try again". That message is not `refused`, so the offline queue sends it again. Before, staff were told the guest was "not on this event's list" and the scan was dropped. A refused door-crew read (`assertDoorCrew`) no longer says "Only the couple or a coordinator…". `checkTicketLive` now answers `unreadable` for it instead of `unknown`. Only the desk calls `checkTicketLive`, and the desk's page lets in couple and coordinator only, so no other crew reach it.
- **Entrance seating chart, 3D seat plan, tea-ceremony order.** These now use `fetchGuestsByEventMeasured`. A refused read shows `ReadRefusedNotice` instead of an empty "0 seated" chart.

SPEC IMPACT: None. These are copy and state fixes inside rulings already made: reads-are-honest, the one stranger's door, and the couple's "may not spend" ceiling of 0.
