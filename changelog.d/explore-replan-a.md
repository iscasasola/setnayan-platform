## 2026-07-27 · feat(vendors): Explore Replan slice A — a `'complete'` category decision, the post-lock "done, or add another?" toast, and the "✓ Covered — reopen" bench collapse (flag-dark)

First slice of the Explore Replan wave (`Explore_Replan_BUILD_SPEC_2026-07-27.md` §3 PR-A). Multi-lock is the shipped default everywhere except `HARD_SINGLE_PICK_GROUPS`, and "at least 1 is the floor" (#3789) — but nothing ever asked the couple whether the floor was also the CEILING. A locked photographer left the rail wide open with no way to say "that's my photographer, stop showing me photographers". This adds that answer as a first-class, reversible decision.

**The state.** `event_category_decisions` (migration `20270110320013` — couple-own RLS, unique `(event_id, plan_group_id)`) gains a third `decision` value: `'complete'` = the couple's explicit "I'm done with this category". Migration `20271012100000` widens the CHECK to `('excluded','deferred','complete')` by drop + re-add; the table, its unique key, its RLS policies and its ACL are untouched, and no new object is created (so no `REVOKE ALL` is owed). `lib/checklist-state.ts` types the value and resolves it to state `'done'` — an explicit "I'm done" outranks the vendor-status derivation, so a category counts as covered even when no `event_vendors` row has reached `delivered`. `'excluded'` / `'deferred'` still short-circuit ahead of it, unchanged. Note the only production caller today (`vendor-category-progress.ts`) passes `decision: null`, so the new branch is spec-forward until PR-B reads decisions on the strip.

**The write paths.** New `vendors/category-decision-actions.ts` — `markCategoryComplete` (upsert on the unique key) and `clearCategoryDecision` (delete the row; state falls back to derivation). These are the first real writers of the table. Two producers feed them:

- **Multi-pick → the toast asks.** `LockMilestoneToast` (`_components/lock-milestone.tsx`) gained `askDone` / `groupLabel` / `onDone` / `onAddAnother` and renders a two-button row — "Done with {group}, or add another?" · "✓ I'm done" writes `complete` · "＋ Add another" just dismisses and leaves the rail open. `accordion-lock.tsx` sets `askDone` only for non-hard-single groups, and the 8-second auto-dismiss is suspended while the question is on screen so the toast can't evaporate mid-decision.
- **Hard-single → auto-completes.** A hard-single lock FILLS the slot, so `finalizeVendor` (`vendors/actions.ts`) upserts `complete` itself right after the milestone block. Best-effort inside a try/catch: an auto-complete failure never rolls back a lock the couple just paid attention to.

**Undo stays honest.** `revertVendorToConsidering` deletes any `'complete'` row for the reverted vendor's plan group. Deliberately NOT flag-gated — rows written while the flag was ON must remain clearable after it's flipped OFF — and it is a no-op delete otherwise (`.eq('decision','complete')` can never touch an `'excluded'` / `'deferred'` row).

**The bench collapse.** `shortlist-categories.tsx` takes a new optional `coveredByTile` prop: a covered tile shows a "✓ Covered" chip in its header and, when expanded, a single "✓ Covered — you're done with {label}." line with a **Reopen** button (→ `clearCategoryDecision` + `router.refresh()`), in place of the vendor rail. `vendors/page.tsx` builds the map — decisions key on `plan_group_id` while the bench renders at TILE grain, so it bridges across `PLAN_GROUPS[].catalogTile`. The read is fail-soft (a query error degrades to the normal rails, never a broken bench) and returns `{}` **before issuing any query** when the flag is off.

**Flag.** New `lib/explore-replan-flag.ts` · `isExploreReplanEnabled()` reading `NEXT_PUBLIC_EXPLORE_REPLAN_ENABLED`, mirroring `payment-gated-lock.ts`; default OFF, `NEXT_PUBLIC_` so the toast (client) and the auto-complete (server) read the same value. **Flag OFF is behaviorally identical to pre-replan production, audited hunk by hunk:** the page issues zero extra queries and passes `{}`, so every tile falls through the original ternary and no "✓ Covered" chip renders; `askDone` resolves `false`, so the toast renders its existing markup and keeps its existing auto-dismiss; `finalizeVendor`'s upsert is skipped entirely; and the new `'complete'` branch in `resolveCategoryState` is unreachable because no writer can produce the value. The one ungated addition is the undo-path delete, which is a no-op query against rows that cannot exist while the flag has never been on. Never flip in prod — the owner flips after previewing.

**Ordering hazard, called out deliberately:** the migration must be dispatched and the CONSTRAINT verified **as an object** (`pg_get_constraintdef`, not `schema_migrations` — the ledger lies) BEFORE the flag is flipped anywhere. Flipping first would make every `'complete'` write fail the old CHECK with `23514`; `finalizeVendor` swallows it by design and the toast's `onDone` ignores the returned error, so "✓ I'm done" would fail silently rather than loudly.

Tests — new `lib/checklist-state.test.ts` (6 cases): `'complete'` → `'done'` with no vendors and with mid-flight (`shortlisted` / `contracted`) vendors; `'excluded'` / `'deferred'` still outrank; a null decision leaves the whole status derivation byte-identical; and the `vendor_status` enum's own `'complete'` value still derives `'done'` without shadowing the decision of the same name. `tsc --noEmit` clean · `next lint` exit 0 with 13 pre-existing warnings, none in any touched file · `pnpm run test:unit` 4252/4252 green (4246 before this branch).
