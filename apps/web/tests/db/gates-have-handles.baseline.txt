# Switch columns with no writer — the standing bill.
#
# FORMAT   <table>.<column> | <why it is allowed to have no writer>
# READ BY  tests/db/gates-have-handles.db.test.ts (inside a REQUIRED check)
#
# ── WHY THIS FILE EXISTS ────────────────────────────────────────────────────
# A "gate with no handle" is a column whose whole job is to be TURNED ON, that
# nothing anywhere can turn on. It is invisible to every ordinary check: it
# typechecks, it has RLS, it has a migration with a thoughtful comment, its
# readers have tests, and the feature simply always takes the false branch.
# Nothing errors. Production looks calm. Five shipped that way before this
# guard enumerated anything:
#
#   papic_face_mode             stored nothing for seven weeks, on a paid feature
#   live_media_public           hid the broadcast from every uninvited visitor
#   author_named_publicly       a guest could never choose to be named
#   is_founder                  no second business could ever be made a founder
#   live_photo_wall_visibility  the couple could not stop the wall on 100 phones
#
# ── WHAT CHANGED 2026-08-17 ─────────────────────────────────────────────────
# Until today the guard checked FIVE HAND-TYPED columns. A new switch was
# covered only if whoever added it remembered to register it — which is exactly
# the memory the guard exists to replace, and is why instances 3, 4 and 5 were
# each registered only AFTER shipping broken.
#
# The candidate set is now DERIVED from the schema: every boolean or enum
# column carrying a DEFAULT (265 of them today). A column leaves the list by
# acquiring a writer, or by earning a line here.
#
# ⚠ A BASELINE IS A BILL, NOT A DECISION. Every line below is somebody deciding
# that a switch may ship with nothing able to flip it. Adding a line is allowed
# — that is the point — but it lands in the diff where a reviewer can disagree.
#
# ── HONESTY NOTE ON THIS FIRST SEEDING ──────────────────────────────────────
# These 50 lines are the INHERITED bill, seeded the day the guard learned to
# enumerate. Where a column carries a comment from its author, the reason below
# is that author's stated intent. Where it does not, the line says exactly what
# was and was not established. "NOT INVESTIGATED" is an honest line; a made-up
# rationale is not. ZERO are now marked FINDING — all four first-seeding findings
# were re-measured and none survived as stated.
#
# ⚖ THE COUNT CAME DOWN BY MEASUREMENT, NOT BY TRIMMING — and it went to ZERO.
# Four were marked FINDING on the first seeding. ONE was a defect in the DETECTOR,
# not the schema (PR #4490, removed from this file). THREE WERE MINE, all the same
# error: I had the fact (nothing writes the column) and invented the consequence
# (therefore the feature is broken). Two were re-checked against live production
# VALUES; the third against its READERS — it has none, so the gate it appeared to
# close was never consulted.
#
# 🔑 THE QUESTION THIS FILE ASKS IS "can anything WRITE it?". That is the right
# question for a switch, and it is NOT sufficient to conclude a feature is broken.
# Before calling a gate shut, ask what READS it: a column with no writer AND no
# reader is vestigial, and one whose value was seeded ON needs no writer at all.
# Both mistakes are recorded in the lines below rather than deleted.
# 🔑 A LIST WITH WRONG ENTRIES ON IT STOPS BEING READ — the whole reason
# this file has to be re-measured rather than defended.

# detector limitation — recorded separately rather than lumped together.
