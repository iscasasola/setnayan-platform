## 2026-11-04 · feat(schedule): a booked supplier picks the chapters they serve — a request the host OKs; the host can still pick for them

Owner ruling 2026-11-04 (DECISION_LOG "CHAPTERS: THE SUPPLIER PICKS, AND THE HOST CAN ALSO PICK FOR THEM"): *"They can pick and we can also pick for them."*

- **Supplier — Customer › Schedule › Where.** One dropdown of the event's chapters (the shared `ChosenRow` + PickMenu ticks). A tick only changes the draft; **Send** writes ONE request (`supplier_ask_where`), so the host is told once. While it waits: "Asked: … · Waiting for the host" and **Take back** (the shipped `withdraw_schedule_request`). Auto-agree on → **Save**, applied at once. On no chapter yet, the dropdown starts on the trade's usual chapters (`service_categories.default_chapters`), a prefill only. A shop booked twice gets one row per booking; a coordinator gets none (on every chapter).
- **Host.** The pick lands in the Schedule's Requests sheet as "Where they go · Now → Asked" with **OK** · Decline · **Change** (opens Suppliers, where `set_supplier_where` still applies at once). The notice is the new in-app-only `supplier_where_asked` — NOT `schedule_change_requested`, which is emailed (owner: no new emails).
- **Locked supplier.** The part lock already refused `set_supplier_where` putting a locked shop on or off a chapter; the host's Where row now says the database's own line and offers **Send them a request** (`host_ask_supplier_where`, which writes the supplier's in-app `schedule_ask` notice in the same statement). The supplier answers in "Asked of you": "Cale (host) asks you to work Reception" · Accept / Decline.
- **Admin › Events › one event › Suppliers' schedule** shows each supplier's Where and any Where request waiting either way.
- **Database (20271308386601 + 20271308641275).** No new table: kind `where` on `event_schedule_suggestions` with `where_vendor_id` + `proposed_block_ids`; a RESTRICTIVE policy makes the two definer doors the only writers; `apply_supplier_where` (called by the ONE accept path) writes `responsible_vendor_ids` exactly as asked; the part lock passes it by the venue-hours pattern (a transaction flag naming the open request + a data check that the write is exactly what it proposed — one clause added to 20271307658341's body, verbatim otherwise); a trigger keeps a Where request's facts fixed so a host cannot rewrite one and approve it past the lock.
