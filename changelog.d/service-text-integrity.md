## 2026-07-27 · feat(vendor-services): flag-dark card-text gate — a `card` profile on the shipped detector, and blanks auto-named instead of refused

A vendor card is a public surface, so a phone number typed into an inclusion label leaks the relationship off Setnayan in front of every couple who opens it. New `lib/service-text-integrity.ts` closes that: a field-aware wrapper that reuses the **shipped chat contact filter's `evaluateMessage()`** (no new detection rules — tune them in `lib/chat-contact-filter.ts`, never here), wired at the save path of `createVendorService` / `updateVendorService` / `commitVendorService` (services) and `savePackage` (packages). Every check runs before its action's first DB write, so a bounce can never leave a partial save; services bounce through the existing `?error=` redirect (the wizard through its claim-preserving `back()`), packages through the existing `{ status: 'invalid', problems }` channel. Gated on `NEXT_PUBLIC_SERVICE_TEXT_INTEGRITY_ENABLED` — **default OFF**, and with the flag off the wrapper returns before it reads a single field, so the save paths are byte-identical to before.

Three things the first cut got wrong, all measured by executing the shipped code:

- **`evaluateMessage(body, profile)` now takes a profile, because card text is not chat text.** The chat rules were written for a message and, applied to a card, refused honest copy: `Instagram teaser reel` / `TikTok highlights package` / `FB live streaming add-on` (on a card these name DELIVERABLES — Setnayan's own SKU copy, "Patiktok — 250 TikTok recordings", was refused too), `Php 9,000 per hour, minimum 4 hours, 150 pax, 20 staff` and `Valid 2026-09-17 - 2026-12-31` (digits fusing into a PH-mobile shape), and `Message me on Setnayan for the full menu` (a solicitation pointing *at* us). `'chat'` is the **default argument** and is untouched — every existing chat caller passes one argument and is byte-identical. `'card'` differs in exactly four ways: Tier-1 phone filler gap 2 instead of 20; Tier-2 (dense 11+ digit run) skipped; blocklist entries of category `app_name` + `euphemism` skipped (driven off the category, not hand-picked regexes); and the `solicit` rule — and only that rule — reading a copy of the body with any "message me on Setnayan" **phrase** scrubbed out. EMAIL / obfuscated email / social URL / bare `@handle` are unchanged in both profiles — so `Coverage @Tagaytay` is still refused, a deliberate over-block (HANDLE cannot tell a venue from `@juanphotos`).

  The (d) exemption is scoped to the phrase because the first cut scoped it to the whole message, and that was a bypass: since `app_name` is also skipped on a card, a vendor could name another platform, point at it, and then say "Setnayan" to disarm the rule. Measured passing under `'card'` and blocking under `'chat'`: `Message me on Viber, not on Setnayan` · `We reply on Setnayan or add me on WhatsApp` · `reach me on IG, we are on Setnayan too`. All three now block on `solicit`. The honest case is a vendor saying "ask me HERE", and the phrase that makes it honest is the destination — so only that phrase earns the exemption, and any other solicitation in the same string still blocks.
- **A blank never refuses a save; we auto-name it** (owner: *"saving builds blank will make us autocreate a name for the build"*). `findVendorTextViolation` no longer has a `required` flag or a blank branch — a blank field is skipped — and new `autoName(kind, index)` returns 1-based `Item N` / `Option N` / `Inclusion N` / `Package N`. `savePackage` fills blank item descriptions and blank option labels before the write; the package editor's `addChoice` seeds two options with `label: ''` and `validatePackageDraft` has no blank-option rule, so those were reaching the DB. Services need no auto-naming: `parseInclusionRows` / `parseDiscountRows` already drop a blank row before the write.
- **The package editor now shows the violation.** `res.status === 'invalid'` set a fixed *"see the notes below"* and never read `res.problems`; the inline notes come from a client-side `validatePackageDraft` that cannot know about a server-only rule, so the vendor saw a pointer to notes that did not exist — an unrecoverable dead end. The `invalid` branch renders `res.problems[].message` into the existing `role="alert"` surface, keeping the fixed string only as the empty-problems fallback.

One trade is written down rather than left to be discovered: skipping `app_name` means a bare platform name with **no destination** (`Viber only`, `Faster on Viber than on Setnayan`) passes on a card. That is the price of allowing `Instagram teaser reel`, and it is affordable because a bare name carries no way to reach the vendor — the moment it acquires one, a rule that is still live on cards fires (`solicit`, HANDLE, SOCIAL_URL, or `phone`).

Covered by `lib/chat-contact-filter.profiles.test.ts` (new file — the whole profile matrix, the default-argument proof, the bypass fixtures, and every phone disguise re-asserted under `'card'`) and the extended `lib/service-text-integrity.test.ts`. Each of the four `card` differences was neutralised one at a time and confirmed to fail a test, plus a fifth sabotage reverting (d) to the whole-body test.
