# ── THE MIRROR OF gates-have-handles.baseline.txt ───────────────────────────
# That file catches a switch NOTHING CAN TURN ON. This one catches a switch that
# turns NOTHING ON. To the person using the product they are the same bug: the
# setting does nothing.
#
# It exists because the second shape shipped live and was found by ACCIDENT on
# 2026-08-17, while chasing an unrelated question:
#
#   users.planner_mode — written by the profile page's Guided / DIY control, with
#   copy beside it promising "Guided shows the 9-step checklist on your Overview
#   tab. DIY hides it so you can plan on your own." FIVE references in the whole
#   repo, all five that page and its own action. Nothing on the Overview reads
#   it. A couple who picks DIY to hide the checklist still sees it.
#
# The enumerating switches guard passed it, correctly and uselessly: the column
# IS written. Nobody had asked the other half of the question.
#
# ── HOW TO READ A LINE HERE ────────────────────────────────────────────────
# ⚠ BEING ON THIS LIST IS NOT A BUG. A switch read only by its own surface is
# perfectly correct when the effect IS on that surface — a vendor toggling
# something in their own shop settings, read by their own shop screens. It
# becomes a defect only when the control PROMISES AN EFFECT SOMEWHERE ELSE, and
# that is a copy question no scanner can answer.
#
# So the honest question for each line is not "is it read elsewhere?" but:
#
#     Does the text next to this control promise something it does not do?
#
# ⚠ A BASELINE IS A BILL. Each line is somebody deciding a control's promise has
# been checked against its wiring. Adding one is allowed; adding one silently is
# not.
