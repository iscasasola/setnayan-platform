## 2026-09-11 · fix(links): no next/link prefetches an /api/ route — OAuth starts and downloads are plain links

Found by the Story's step-8 live drive: every visit to a host's Papic studio (`/dashboard/{id}/studio/papic`) logged a CORS error and posted a CSP `connect-src` report to `/api/csp-report`. `<Link>` prefetches the hrefs in view, and "Connect Google Drive" pointed at `/api/oauth/drive/start`, which answers 302 → accounts.google.com, so the prefetch (a fetch) followed the redirect cross-origin and was refused. Nothing looked broken; every console-error / CSP check was polluted and a CSP report went out per page view.

- Population DERIVED, not listed: 12 next/link `<Link>`s with an `/api/` href on the tag, plus 3 that receive one through a prop (`DriveConnectCard`/`DriveReconnectBanner` in `app/_components/drive-connect-card.tsx`, `RecapDriveNudge`) — 15, not the 5 the finding named. 14 become plain `<a>` (OAuth starts for Drive, YouTube, TikTok, photo delivery; the budget .ics download) — a full navigation is what a person needs there. `/api/v1` is a real docs PAGE (Next's `no-html-link-for-pages` rule says so), so it stays a `<Link>` with `prefetch={false}`.
- Guard `lib/no-link-prefetches-an-api-route.test.ts`: no next/link `<Link>` has an `/api/` href without `prefetch={false}` — on the tag, or through a prop traced from the caller (`<Comp connectHref={`/api/…`}>`) into the component's own `<Link href={connectHref}>`. Source read through `lib/strip-comments.ts`; a detector self-test; population floors (1,289 Link tags scanned, 6 `/api/` props traced). Sabotage, measured: one Drive `<a>` back to `<Link>` (papic page `<Link` 8 → 9) → offenders 0 → 1, fail; the reconnect banner back to `<Link>` (drive-connect-card `<Link` 1 → 2) → offenders 0 → 2 (two callers feed it), fail.
