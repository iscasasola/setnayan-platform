## 2026-10-02 · feat(ugat): Root map part 2 — Fields, one-home, saved-and-used, landing and shown-values checks, ratchet on

Root map (code name Ugat) part 2, per DECISION_LOG 2026-10-02 "ONE MAP OF THE APP", "EVERY ANSWER ABOUT AN EVENT LIVES IN EVENT DETAILS — ONE HOME, MAPPED", "THE ROOT MAP ALSO CATCHES 'PRESSED BUT WENT TO THE WRONG PLACE' AND 'FILLED IN BUT NOT SAVED'", "…A NUMBER THAT LOOKS LIVE BUT IS TYPED IN" and "TWO MORE THINGS EVERY BUILD IS CHECKED FOR".

- **Fields layer** — `lib/ugat/fields.ts` (shape, `CALCULATIONS`, fact names), `lib/ugat/scan-fields.ts` (scanner), `lib/ugat/fields.generated.json` (committed, keyed by the Screens-layer ids), `pnpm --filter @setnayan/web ugat:fields`. Every screen's reads (`table.column`), writes (incl. jsonb keys and rpc params), reachable actions and calculations; every action's form fields and where each one is saved; every `<form>` and the action it posts to.
- **One-home check** — `lib/ugat/root-map-checks.ts` `oneHomeFindings`: (a) one fact saved in two homes (a table holding it as a column AND inside a jsonb blob, an `events` column copied into another event-record table, or a browser-store copy) — snapshots, ledgers, tokens and logs copy on purpose and are excluded; (b) an `events` answer saved by a screen while Event Details › Your info (`/details` + `/details/change`) neither reads nor writes that column. App-state columns (`…_status`, tokens, counters, dismissed hints) are not answers (`isEventBookkeeping`).
- **Saved-and-used check** — filled-but-dropped (a form input its action never reads; an action field whose value reaches no write, row key, call, return or write-guarding `if`), saved-but-never-used (`lib/ugat/scan-readers.ts` `scanReaders`: a written column no select, row property, filter, string or migration SQL reads), and sanitisers that keep only known keys before a save (`scanSanitizers`). `lib/ugat/round-trip.ts` follows one create form input → field → home → reading screen; `create-forms-round-trip.test.ts` applies it to nine create forms (guest, schedule moment, sponsor, table, budget line, gig, supplier service, payment method, Samahan community).
- **Landing check** — `lib/ugat/scan-landings.ts`: a door's `#section` must exist in the destination's code (or the same page's, for `#x`); the words on a tapped link must name where it lands (title, masthead, menu label, address words, through a reasoned `LANDING_SYNONYMS`; generic calls to action are not judged); a door that lands on a forwarding stub is "retarget". `scanScreens` gains an `onDoor` hook so the landing check reuses part 1's door resolution.
- **Shown-values check** — `lib/ugat/scan-shown-values.ts`: a digit next to days/guests/pax/tables/seats/photos/couples/%/₱ typed into a screen's text (JSX text or a string in a `.tsx`), with a reasoned `RULE_CONSTANTS` allowlist (time windows, policy percentages, ₱0, size menus, limits, ranges, the 28-day cycle); and one calculation (`CALCULATIONS`) computed or drawn by two components on one screen. `lib/ugat/output-moves.ts` (`assertOutputMoves`): move the input, the output must move — applied to Home's days to go (two todays, two dates), coming and no reply (two guest lists) in `app/dashboard/[eventId]/home-numbers-move.test.ts`, rendering the real `HomeFirstScreen` through the same functions page.tsx calls.
- **Ratchet ON** — `RATCHET_ENFORCED = true` in `apps/web/scripts/check-ugat-screens.mjs`, which now also runs `scripts/root-map.ts --check` (`pnpm --filter @setnayan/web root-map`). CI fails on a NEW no-door screen, door to nowhere, missing #section, one-fact-two-homes, event answer outside Your info, filled-but-dropped field, typed live number or fact shown twice; door words, retarget, never-read and sanitisers warn. Today's 488 findings are in `apps/web/lib/ugat/baselines/<check>.baseline.txt`, one per line with its reason (`key<TAB># why`); `root-map --baseline` is their only writer. STRICT (controller decision on #6285): for an enforced check, a fixed finding whose line is still listed also fails CI ("fixed — remove this line from <baseline file> (run root-map --baseline)"), so a fixed problem cannot quietly come back; the warn-only checks just print a hint. Part 1's `screens-no-door.baseline.txt` moved into `baselines/no-door.baseline.txt`. The CI step is renamed "Root map is current and ratcheted".
- The Fields map is NOT committed (git-ignored `fields.generated.json`, written by `ugat:fields` for reading): it changes with almost every select or form and is regenerated on every CI run, so a committed copy could only be stale.
